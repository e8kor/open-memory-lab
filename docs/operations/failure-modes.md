# Failure modes

When the server cannot establish that an act is permitted and durable, the act does not happen. It refuses with a typed code from the [error list](../api/errors.md). Each row below is one failure on its own. For steps, see [operational alerts](runbooks.md). For the signals, see [Monitor an OML server](observability.md).

| Failure | What the server does | What is seen | What to do |
|---|---|---|---|
| Postgres primary unreachable | Refuses every write and read, because the serving store is the store that is down. | `system.unavailable` (503, retryable). `/readyz` fails. | Restore Postgres. Clients retry on their own. |
| Stored chain head does not verify at start (fork check) | Refuses writes and stays down. It never signs on top of a fork. | `/readyz` fails. Writes return `system.unavailable`. | Follow [fork check failing](runbooks.md#fork-check-failing). |
| Lead takes over | Refuses writes until a new lead holds the lease and passes the fork check. | A short burst of `system.unavailable` on writes. | Retry. If it repeats, see [lead takeovers repeat](runbooks.md#lead-takeovers-repeat). |
| Keyring file (`kms.keyring_path`) unreadable | Refuses writes, because nothing can be encrypted. Reads of cached keys keep working until the cache expires. | `system.unavailable`. | Restore the keyring file. |
| Scan rule set fails to load | The server reports not ready and serves nothing. It never admits an unscanned write. | `/readyz` fails. `oml doctor` shows `scan_ruleset` or `scan_rules`. | Fix the rule set the server names, then restart. |
| Scan fails on one write | Refuses that write. | `system.internal`. | Retry. If it repeats, send the `request_id` to the operator. |
| A held version has a stored scan finding but no findings list | Serves it as before; the review card shows the stored finding alone. An older server wrote it while migration 0043 ran; an older binary refuses to start once 0043 has run ([ADR-0074](../adr/ADR-0074-the-scan-names-a-threat-class-for-every-finding-refuses-only-what-can-never-be-safe-holds-or-annotates-the-rest-and-recall-serves-every-hit-as-data-with-its-findings.md) d23). | `oml doctor` warns `scan_findings_unlisted: n`. | Run `oml admin rescan --record-held`, which lists the findings of each held version. |
| A promoted version has no approval | Serves it as before, with `approver` and `approved_at` null. Migration 0044's fill found no verdict in the journal for its promotion ([ADR-0077](../adr/ADR-0077-a-served-memory-says-when-it-was-approved-and-by-what-kind-of-reviewer-and-never-names-the-reviewer.md) d6). | `oml doctor` warns `approval_unmatched: n`, read by an admin key from `promoted_unapproved` on `GET /v2/admin/rescan`: the count of served versions with no approval. No command lists which they are; a reader sees one as a memory whose `approver` is null. | Supersede the version with `oml write --replaces` and have a reviewer approve the successor: the count falls by one when the successor is approved. Or leave it. |
| Object store at `storage.url` fails (directory missing, full or not writable) | Starts and serves every other route: the store is opened on first use, so one that cannot be created never stops the start. Refuses the upload act that needed it and changes no session's state; the sweep shreds expired sessions' keys before it removes their parts, so a part it cannot remove is ciphertext no key opens ([ADR-0004](../adr/ADR-0004-bodies-and-attachments.md) d3). | `upload.storage_failed` (503, retryable). `oml doctor` warns `upload_store_unavailable` with the reason while the directory cannot be opened, and `upload_unswept` and `upload_sweep_failed`; the log names `upload_store_unavailable` once at start and `upload_sweep_failed`. | Make the directory writable by the server, with space. The next sweep removes what is left. |
| The lead stops while an import runs | The import's row stays `running`; every version it wrote stays held by the importer, and the upload stays bound. An hour after the import began, the next upload sweep ends it `failed`, nulls the upload's key and removes its parts ([ADR-0084](../adr/ADR-0084-a-workspace-moves-between-servers-as-a-signed-bundle-that-lands-held-or-in-progress-and-is-reviewed-again-unless-its-source-server-is-pinned.md) d11, I11). | `oml doctor` warns `imports_stopped` for an import running more than an hour; `GET /v2/imports/{id}` answers its `position`; the log names `imports_stopped` when the sweep ends one. | Upload the bundle again and import it into the same target: each version's idempotency key makes the written ones no-ops. |
| An import's end cannot shred its upload's key (the store failed) | The import ends as it would; its upload stays bound with its key set, until the next sweep nulls the key of every bound upload whose import ended ([ADR-0084](../adr/ADR-0084-a-workspace-moves-between-servers-as-a-signed-bundle-that-lands-held-or-in-progress-and-is-reviewed-again-unless-its-source-server-is-pinned.md) I11). | The log names `import_shred_failed`; `oml doctor` warns `upload_staging_stale` for a bound upload whose key is still set 24 hours after binding. | Restore the database's health; the next sweep shreds the key. |
| A tenant starts a second import, or the server runs two | Nothing is read or written ([ADR-0084](../adr/ADR-0084-a-workspace-moves-between-servers-as-a-signed-bundle-that-lands-held-or-in-progress-and-is-reviewed-again-unless-its-source-server-is-pinned.md) I13). | `import.busy` (409, retryable); `export.busy` (409, retryable) for a second export of one tenant. | Retry when the running one ends. |
| A version carries an import's idempotency key and no provenance | No build that records provenance in the write's commit leaves one ([ADR-0084](../adr/ADR-0084-a-workspace-moves-between-servers-as-a-signed-bundle-that-lands-held-or-in-progress-and-is-reviewed-again-unless-its-source-server-is-pinned.md) I14). | `oml doctor` warns `imports_unprovenanced`. | Report it as a defect, with the version ids. |
| A bundle fails verification | Writes nothing, binds no upload and journals nothing (d7). | The refusal's `bundle.*` code; `oml doctor` lists `import_refusals` by code. | Ask the source for a fresh export; a `bundle.signature_unexpected` or `import.source_key_changed` means the key is not the one expected: confirm it out of band. |
| A workspace export is refused by the tenant's export policy, or a node of its subtree is unreadable | Writes no bundle and journals nothing. The policy is `own_root` until an admin route sets another: a person exports only inside their own root ([ADR-0084](../adr/ADR-0084-a-workspace-moves-between-servers-as-a-signed-bundle-that-lands-held-or-in-progress-and-is-reviewed-again-unless-its-source-server-is-pinned.md) d10). | `export.disabled` (403, `details.reason` `off` or `own_root`) or `export.not_readable` (403). `oml doctor` names the policy under `exports`, and counts bundles served from `oml_exports_total`. | Export a workspace inside the person's own root, or one every node of which the key reads. A shared workspace needs an admin's allowance, whose route is not built yet. |
| A workspace holds steering or guardrail versions no person can approve | Holds them for good: only a person's reviewer key approves an instruction ([ADR-0080](../adr/ADR-0080-a-skill-is-a-reviewed-claim-the-mcp-server-lists-as-a-prompt-and-serves-as-a-resource-loaded-live-and-never-copied.md) d16), and the workspace's reviewer keys are agents'. | `oml doctor` warns `instructions_unreviewable: <path> holds <n> …`, read by an admin key from `held_instructions` and `person_reviewers` on `GET /v2/review/queue`. The count overcounts: a person's key whose person also wrote the held instructions is counted, though outside that person's own root it cannot approve them, so doctor stays silent where that person's key is the only one. | Issue a reviewer key with `--used-by person` and a reviewer grant on the workspace, or approve in the console. |
| A steering or guardrail version in force was approved by a key that is not a person's | Serves it as before. Only a person's reviewer key approves an instruction since v0.8.3, and nothing approved earlier was demoted ([ADR-0080](../adr/ADR-0080-a-skill-is-a-reviewed-claim-the-mcp-server-lists-as-a-prompt-and-serves-as-a-resource-loaded-live-and-never-copied.md) d16). | `oml doctor` warns `instruction_approvals: n`, read by an admin key from `instructions_without_person_approval` on `GET /v2/admin/rescan`. A count only; the admin read (`POST /v2/admin/memories/search`) finds the versions. A version a person's key approved while that key had a crew is not counted, since the row keeps only `used_by` (#460). | Have a person supersede each with the same text and approve the successor, or leave it. |
| Search index behind | Recall misses memories approved after the backlog. Get by id is unaffected. | Fewer hits. `oml_sparse_backlog` rises when the sparse encoder is on. | Wait for the backlog to drain. Check `oml doctor` search lines. |
| Reranker slow or failing | Skips reranking and returns the unreranked order. | `oml_reranks_total{outcome="skipped"}` rises. `oml doctor` warns. | See [troubleshooting the server](../help/troubleshooting-server.md#search-model-files-are-missing). |
| Lake writer stopped or behind | Nothing client-facing changes. The lake serves no client read. | `oml_lake_lag_seconds` grows. | Follow [the lake falls behind](runbooks.md#the-lake-falls-behind). |
| No reviewer available | Accepts writes and holds them. It does not refuse them. | Memories stay `held`. `oml doctor` reports review capacity. | Follow [no reviewer can approve](runbooks.md#no-reviewer-can-approve). |
| A web console act's outcome is not recorded after it commits (Postgres fails between the act and its record, a step after the commit fails, or the lead stops there) | Answers the act's outcome when it can. A request dropped mid-act does not stop the act: it records its outcome and the resubmission replays it. Otherwise the act's claim on its `Idempotency-Key` stays, so a resubmission of that form waits 5 s and answers `idempotency.in_progress` instead of acting again. | `409 idempotency.in_progress` on a resubmitted form. `oml_idempotency_unsettled_total` rises when the lead saw the failure, and `oml doctor` warns. | Nothing to repair: a fresh form acts under a fresh key. If Postgres was failing, restore it. See [a form answers idempotency.in_progress](runbooks.md#a-form-answers-idempotencyin_progress). |
| `oml-web`'s secret weak, missing, set twice, or in a file others can read | `oml-web` (or the server, for its own setting) refuses to start, naming the setting and, for a file, its path and mode, never the value. | The process exits. `oml-web --doctor` prints a `fail` line naming the setting. | Set one secret of at least 32 visible ASCII characters, 8 of them distinct, in an owner-only file or the environment ([Run the web console](web-console.md#store-the-client-secret)). |
| The server refuses `oml-web`'s secret: different values, no `web.client_secret` on the server, a proxy that adds a client-certificate header, a rotation done out of order, or a previous secret past `web.client_secret_previous_until` | Refuses every capacity credential `oml-web` presents as `auth.invalid` `session_outside_web`. | Every page sends people back to sign-in. `oml-web --doctor` prints `fail api: ... refuses oml-web's web.client_secret`. A server start with a closed window logs `web_client_previous_closed`. | Set the same value on both, or keep the old one on the server as `web.client_secret_previous` while `oml-web` restarts ([Rotating the client secret](web-console.md#rotating-the-client-secret)). Strip client-certificate headers at the proxy. |
| A person's linked key is revoked, past its expiry, unlinked or linked to another person, or `oml-web` sends `OML-Acting-Key` without its client identity | The console's act with that key answers `auth.invalid` with `details.reason: acting_key_not_linked` and runs nothing ([ADR-0085](../adr/ADR-0085-a-workspace-publishes-immutable-releases-that-one-person-cuts-and-another-ratifies-and-each-key-binds-to-the-tip-the-latest-release-or-a-pinned-one.md) d16). | The page names the refusal. The key leaves the person's `linked_keys` in `GET /v2/whoami`, so the Review page stops offering it. The request log carries `acting_for`. `oml-web --doctor` prints `fail api: ... refuses oml-web's web.client_secret` when the identity is the cause. | A console admin links a live key, or unlinks the dead one, on the admin Keys page. |
| Metrics listener not set | Serves no `/metrics`. | `oml doctor` says where the counts are. | Set `server.metrics_listen`. |

How long each refusal window lasts has not been measured.
