Open Memory Lab design mockups ADR-0051 · proposed 2026-11-04

Design artefact, not a built feature

Say what a memory is about, in words the crew agreed on

One agent writes “credentials”, another “secrets”, and recall for either misses the other. ADR-0051 gives a crew a few small reviewed vocabularies, one per facet. The writing agent picks up to three terms from candidates the server finds by matching labels; the reviewer sees them with the memory; recall finds memories by the terms a query names, and says which label matched.

Memory texts come from the recall eval (eval/recall/, version 1, synthetic) and the terms from eval/recall/ontology/vocabulary.json. The chart's numbers are the offline run of 2026-11-04 and are upper bounds. Every response field, page layout and identifier on this page is illustrative.

ADR-0051 d3, d4, d5 · illustrative

A write is offered terms and chooses three

The agent asks which terms fit its draft. The server matches labels, nothing more, and returns candidates with the label that matched. The agent chooses two of them and proposes a third concept the vocabulary lacks. Nothing is attached by the server; the reviewer decides the memory and its terms together.

ADR-0051 d6, d7, d8 · illustrative

“credentials” finds the memories about secrets

The query word “credentials” is an alternative label of topic:secrets. The term list brings the memories tagged with it, whatever their text says, fused with BM25's list by reciprocal rank; the third hit is BM25's alone, for the word itself. The query text is never rewritten. Each hit says how it matched.

ADR-0051 d3, d14 · illustrative

The reviewer sees the terms as part of the memory

The serve lists each proposed term with its facet, label, definition and state. The reviewer approves the memory and its terms together, or rejects with a reason that names the term. No verdict adds or removes a term, so review never changes what the memory is found by.

ADR-0051 d13

The build, in increments

  1. O1
    Terms with labels: facets as vocabularies, preferred and alternative labels, terms_for, seeds and SKOS import.

    gate: the seed round-trips the eval vocabulary · not assigned

  2. O2
    about at write: links proposed with the memory, ratified with it; new-term proposals; the reviewer's view.

    after ADR-0046's claim edges and ADR-0050's fields · gate: the R1–R4 tests in both stores · not assigned

  3. O3
    Recall by term: the term retriever, bm25-term, facet filters, the matched label.

    after ADR-0049's port · gate: reproduce +0.03 nDCG@10 in CI; default only on eval v2 (FR-95)

  4. O4
    Doctor lines: orphan facets, waiting terms, broad labels, adoption, the retired-link backlog.

    each planted and caught in a test

  5. —
    Still parked: ontology crews, classifiers, curators rejecting links, releases and the is_a closure (ADR-0027, ADR-0021).

    reopened by FR-97's measurement

What holds at every increment

No model on the server reads a memory to tag it. The author proposes terms, someone else approves them with the memory, and no verdict adds or removes one. A term ranks a memory only through a link its author wrote. Counts and links are shown only to keys that may read both ends. Three MCP tools stay three.
