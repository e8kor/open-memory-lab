- **A disable or a deletion close that meets a concurrent write journals each of its events once** ([ADR-0068](adr/ADR-0068-anyone-signs-in-and-gets-a-private-root-under-quotas-when-the-operator-opens-sign-up.md) d6, d8; issue #266). When another write moves the journal head, each key denial and the closing commit now retry on their own, so a busy server no longer records `web.user_disabled` twice in one request. A key the disable cannot cut off, such as an admin key under the person's root, is skipped and every other key is still cut off. The disable no longer answers an error after the person is disabled, so sending it again under the same `Idempotency-Key` replays the first answer.
