**Every admin act is one journalled record, and widening waits on a second admin person.** [ADR-0097](adr/ADR-0097-every-admin-act-is-one-journalled-record-narrowing-takes-effect-at-once-widening-waits-on-a-second-admin-person-and-every-admin-key-belongs-to-a-person.md) d1, d2, d3, d5, d9, d10, d11, d14 and d23 are built. Every admin act journals one `admin.act` envelope first in the commit of its effect, its class fixed by the act, and the effect's events name its `act_id`; migration 0070 adds the `admin_acts` table, `api_keys.pending_act_id`, `web_emails.admin_since` and `tenants.sole_admin`, backfilled from the journal. An admin key's issuance is widening: in a tenant that has never had two live admin persons it takes effect at once, marked `sole_admin`; otherwise its value is shown once, the key answers `auth.invalid` with `details.reason: pending_confirmation` on every path, and its grants and connect code wait in the act until a second admin person whose admin flag was accepted at least seven days before the act confirms it with `POST /v2/admin/acts/{act}/confirm` (`oml admin confirm`). `POST /v2/admin/acts/{act}/decline` (`oml admin decline`) is final and revokes a key the act issued; a pending act expires as declined after seven days. `GET /v2/admin/acts` (`oml admin acts`) lists the acts. A pending issuance requires a `reason` (`oml keys issue --reason`). An admin key's issuance now commits its act, key, grants and code as one chain, so a refused grant leaves no key behind. `POST /v2/keys/{key}/revoke {reason}` (`oml keys revoke`) ends one key and nothing it issued, by an admin key, or by a person's `<user>-web` session for that person's own keys; a session key, the reserved server key and a revoked key are refused by name. `oml doctor` gains `admin.act_pending_confirmation`, `admin.act_sole_admin`, `admin.act_without_reason` and `admin.act_expired`.
