**Web console.** Every page a signed-in person is shown draws **Sign out** in its header, a refusal page included: a page not found, a form refused, an API refusal shown by its code, and the refusal a cut-off key's act answers (#327; ADR-0070 d2, d3, d5, an amendment the operator accepted on 2026-11-12). The sign-in page, the sign-up terms page and a refusal the server answers before it reads the session draw none. No page offered it before, so a session ended only by expiry, a change to the person's allowlist entry or a new sign-in. The control is a form that posts `sign_out` with the session's CSRF token to the server's `POST /web`, never a link: the server ends the session, so every credential `oml-web` derives from it is `auth.invalid` from the next request, clears the session cookie with the attributes it was set with and returns to the sign-in page. Below 600px the header drops the name and keeps the control. `POST /v2/web/session/end` still serves no page. The header was looked at in Chromium as a static render at 1100px and 390px, before the control's container became a `div` and before the refusal page drew it; neither was looked at since, and the running console was not.
