Added a page, [when a recall repeats](architecture/repeatable-recall.md), and the test behind it (#176): under the default pipeline, `bm25-postings`, the same recall returns the same bytes call after call and from a second server process over the same database, `recall_id` aside. The page lists the inputs that define an answer (the request, the key, the approved set, `now`, the settings and the server version), what changes it between calls, and what is outside it: `timings`, the `search.widen` hint, and the pipelines that read a model. A held write leaves every other key's answer unchanged; its approval changes the answer once. The test runs on 14 approved memories; a score's last digit across PostgreSQL query plans on a large tenant is not proven.
