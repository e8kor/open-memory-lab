The release notes of a release whose scanner rule set differs from the previous tag's carry the line `<!-- oml-deployer: post-step admin-rescan-record-held -->`, a marker an installer may read. v0.7.2 changed the rule set to `oml-scan/1.2` and told operators to run `oml admin rescan --record-held`, but its notes carried nothing a program could read. `scripts/release_markers.py` compares `RULESET` in `crates/oml-scan/src/lib.rs` at the tag with the previous stable tag's; the publish job appends the line and then checks it before it creates the release, naming the line to add when it is missing, and `scripts/check_release.py` holds both steps. Not run against a real release: only a tag shows the workflow producing the line.
