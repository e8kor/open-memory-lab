- **Recall may search the trusted workareas a key already reads** ([ADR-0072](adr/ADR-0072-recall-searches-the-trusted-workareas-a-key-already-reads-chosen-per-query-by-reviewed-descriptors-and-never-widens-what-it-may-read.md), proposed). A `committed` or `validated` workarea outside every in-progress subtree is a trusted source, with no new flag. One `sources` argument on recall, default `"scope"`, takes `"wide"`, which adds the readable trusted sources ordered by exact word counts above a cap, or a fixed list of workareas searched alone and answered whole or refused. Every hit scores with statistics fixed before selection, so no hit's score depends on which sources were chosen, and a `scope` answer says when a wider search would find more. Reviewed descriptors join selection only in phase 2, and a descriptor with a hold finding never advertises. Advertising grants nothing, and no key learns of a workarea it cannot read; discovery without read is a directory workarea. Three phases, each closed by leakage tests, are tracked as issues [#205](https://github.com/e8kor/open-memory-lab/issues/205), [#206](https://github.com/e8kor/open-memory-lab/issues/206) and [#207](https://github.com/e8kor/open-memory-lab/issues/207).
