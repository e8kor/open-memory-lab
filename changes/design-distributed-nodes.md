- **A distributed provider: one lead signs, a standby lead takes over, nodes serve the workareas placed on them** ([ADR-0073](adr/ADR-0073-a-leader-signs-every-write-and-nodes-serve-the-workareas-placed-on-them-each-read-routed-to-the-closest-less-busy-replica-fresh-enough-for-it.md), proposed). Phase 1a is a standby lead on the same database, so restarts and upgrades stop stopping the API with 2 processes and 1 PostgreSQL; the successor takes the lease by term after watching the lead's renewal count stand still on its own clock, never on a wall clock. Phase 1b adds read nodes holding whole tenants, fed the signed journal only up to what the authority's synchronous standby has flushed, each event verified before it is applied; the operator chooses a quorum of two standbys or a degrade mode with an alarm, because a single absent standby holds every commit. Read leases are bound to the term and granted in step with narrowing commits, and a node checks every answer against the narrowing it has reported, so a revoked grant, a denial, a demotion or an erasure applies on every node before its caller hears it took effect, reads in flight included. Each unit's DEKs are wrapped by a unit key that only its nodes receive, inside a lease. Phase 2 adds regions and closest-least-busy routing; phase 3 places workarea subtrees and serves federated recall from snapshots on the sources' own replicas. Amends ADR-0023, ADR-0024, ADR-0002, ADR-0005 and ADR-0042; tracked as [#221](https://github.com/e8kor/open-memory-lab/issues/221), [#209](https://github.com/e8kor/open-memory-lab/issues/209), [#210](https://github.com/e8kor/open-memory-lab/issues/210) and [#211](https://github.com/e8kor/open-memory-lab/issues/211); a Cluster page mockup, not built.
