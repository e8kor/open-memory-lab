**The scan vetoes an age identity.** The rule set is now `oml-scan/1.3`: a write that holds an age X25519 identity (`AGE-SECRET-KEY-1` and 58 bech32 characters), the secret half of a bundle recipient, is refused with `submission.scan_veto`, finding `secret.private_key: age-identity`. The public recipient, `age1…`, passes. After the upgrade run `oml admin rescan --record-held`; until it has run, `scan_held_unrescanned` and `scan_rescan_due` count the versions scanned under `oml-scan/1.2` ([ADR-0065](adr/ADR-0065-the-scan-is-a-versioned-compiled-in-rule-set-that-vetoes-leaked-keys-and-holds-what-a-reviewer-should-judge.md) d1, d2, #453).
