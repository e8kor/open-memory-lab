- **One design system for every surface** ([ADR-0069](adr/ADR-0069-oml-s-design-system-is-the-source-of-truth-for-every-surface.md)). `design/tokens.json`, the state glyphs, the marks and the fonts are copied from the design system, and `scripts/gen_design_tokens.py` writes everything derived from them: the web pages' custom properties and inline wordmark and glyphs, the docs site's Material palette, and the README's review-gate diagram in both themes. The Practices workflow fails a pull request when a generated file is stale (`--check`) or a colour pair drops below its contrast floor (`scripts/check_contrast.py`, 304 pairs). `/web` and `/web/admin` take the design system's header, type, buttons, form controls and focus ring, follow `prefers-color-scheme` into the paper theme, and show each state as a chip with its word, glyph and colour; the CSP still names one hashed stylesheet.
- **The docs site, the README and the landing page source take the design system** ([ADR-0069](adr/ADR-0069-oml-s-design-system-is-the-source-of-truth-for-every-surface.md)). The docs drop Material's `deep purple` palette and Google Fonts for `docs/stylesheets/oml.css`, generated from the tokens, with the fonts served from the site, the mark swapped per theme, admonition and code colours, and the states shown as chips (`docs/includes/states.md`, on the concepts page). The README leads with the wordmark, one line, the review-gate diagram in both themes and three value points. `deploy/landing/index.html` is generated from `index.src.html`; deploying it stays an operator step.
