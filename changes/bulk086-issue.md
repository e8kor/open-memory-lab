**The admin console creates workspaces and issues keys, a key can start with its workspaces, and a grant may carry `create`.** [ADR-0097](adr/ADR-0097-every-admin-act-is-one-journalled-record-narrowing-takes-effect-at-once-widening-waits-on-a-second-admin-person-and-every-admin-key-belongs-to-a-person.md) d29, d30 and d31 are built. The admin Workspaces page gains a create form: `<user>-admin` creates anywhere in the tenant, `universe` included, as a neutral admin act. The admin console gains a key builder at `/web/admin/keys/new`, the personal builder's steps over the tenant's tree with role, grants, default workspace, the user, `used_by`, principal, crew, expiry, rate and a required reason; `POST /v2/keys` admits `<user>-admin` as an admin issuance, so the key waits on a second admin person outside `sole_admin`, and the result page shows the value once and says whether it waits. `POST /v2/keys` takes `create_workspaces[]` (`oml keys issue` and `issue-agent --create-workspace <parent>/<name>`, and a "new workspace" row in both builders): the workspaces, the key and its role's default grants on them commit as one chain, and a pending issuance creates nothing until its confirmation, which creates them in its own commit. A grant takes `create: true` (`--grant <workspace>:<role>:create`, a box per grant in both builders): its key creates child workspaces where the grant reaches, a shared tree included, over HTTP, the CLI and `oml_write`'s `create_workspace`; under a node grant the child gets the same grant in the create's commit, and a frozen parent refuses it with `access.verb_ceiling`, `details.reason: parent_frozen`. Migration 0071 adds `grants.may_create`. A proxy that routes `oml-web`'s paths by name adds `/web/admin/keys/new`, as `deploy/caddy/Caddyfile`, both compose files and the chart's `web.ingressPaths` do.
