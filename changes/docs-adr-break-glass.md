**Design: every admin act is one journalled record, and every admin key belongs to a person.** [ADR-0097](adr/ADR-0097-every-admin-act-is-one-journalled-record-narrowing-takes-effect-at-once-widening-waits-on-a-second-admin-person-and-every-admin-key-belongs-to-a-person.md), accepted design of 2026-11-25, decided by the operator for v0.8.6 and not built. Every act an admin takes outside content review journals one `admin.act` envelope whose act decides its class. Narrowing (denials, demotes, revocation, lower limits) takes effect at once and never reverts by itself; erase demotes at once and shreds only after a second admin person confirms; widening (keys, grants, capacities, connect codes, new admins, limit raises, federation) takes effect only after a second admin person whose entry is at least seven days old confirms it, and reaching into a person's own root is widening with no consent asked. A tenant that has never had two admin persons acts at once, marked `sole_admin`. An act against another admin takes effect at once, is contestable from a contest-only sign-in, suspends the target's admin keys, freezes below three admins and is settled from the host by `oml operator settle`; `oml operator recover` restores a tenant whose admins have been dormant for 30 days. Instruction verdicts, fix settlements and ladder ratifications need a counted person, and admins stay on the ladder with another person ratifying. One plain verb revokes any key, with no cascade. Services hold a counts-only `maintenance` key, the deployer's admin keys are converted in place, and a credential-less server issuer issues session keys. Every admin key is linked to a person and revoked when the person goes, and a bootstrap names a person. Four pieces land in v0.8.5: the read-only production counts, the deny's stored reason, the docs drift, and an unconditional last-admin guard. Amendment notes dated 2026-11-25 are added to ADR-0001 (d5, kept), ADR-0009, ADR-0010, ADR-0031, ADR-0044, ADR-0045, ADR-0079, ADR-0085, ADR-0089, ADR-0093, ADR-0095 and ADR-0096. The operator's answers of the same day to the tensions are recorded: a reach into a person's root under `sole_admin` takes effect at once and notifies the person; keys a second admin confirmed in a root act as the person's own, an accepted residual; a `sole_admin` tenant ratifies its own ladder moves, marked; an admin key links to its holder's person by possession in v0.8.6, in the upgrade window; recovery keeps dormant admins' flags; and a person revokes their own keys.
