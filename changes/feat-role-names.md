**Contributor and submitter replace writer, built.** [ADR-0093](adr/ADR-0093-contributor-and-submitter-replace-writer.md) ships: a key that recalls and writes is a `contributor`, a key that writes without recall is a `submitter`, and the grant role that confers writing is `submitter`. Issuance refuses a contributor without a reader or a submitter grant with `request.validation`, `details.reason: contributor_grants`, and never adds a grant. Migration 0066 rewrites stored writer keys to contributor and writer grants to submitter under each tenant's row security, and signed events are read through rule 7 of the former-name map, so a rebuilt database equals the migrated one. Uploads admit contributor and submitter keys; imports and the user-root workspace create admit a contributor key alone; the curator's ceiling reads `submitter`; a submitter reads its own rows and recalls nothing. `writer` is unknown input on every surface and `oml keys issue-agent --write-only` is retired for `--role submitter`. `oml doctor` names a contributor key without a reader grant (`key_contributor_without_recall`) and the console marks it "no recall"; the console's issue form offers `contributor` and `reader`. The vocabulary lint covers `writer` as a role. Clients upgrade before the server ([upgrades](operations/upgrades.md)).
