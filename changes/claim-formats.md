- **A claim version names its format** ([ADR-0056](adr/ADR-0056-a-claim-version-names-its-format-the-signature-covers-its-source-and-adapters-compiled-into-the-server-derive-what-search-reads.md)). A submission or a supersession may carry `format`, a media type from a closed list (`text/plain` by default, `text/markdown`, `text/vnd.oml.mermaid`, `application/json`, `application/yaml`, `text/vnd.oml.code; lang=<language>`), and a one-line `title`, required with any format that is not prose. Both are signed with the version and fixed for it, so a format changes only by supersession; the source is stored and signed exactly as sent. Adapters compiled into the server validate each source, refuse by name what they will not draw or parse (`submission.format_invalid`), derive the text search reads (`memories.search_text`, read by the lexemes, the postings, the vocabulary, the sparse encoder and the reranker), and scan the decoded values of a JSON or YAML document as well as its source, so a format only adds findings. Every claim item carries `format` and `title`; the SDKs gain `fence_for`. Mermaid is drawn on the review card in a sandboxed frame under its own policy, with the pinned bundle vendored. Migrations 0033 to 0035 add the columns, validate their checks outside a transaction and key the near-copy check on the search text; every existing claim is `text/plain`.
