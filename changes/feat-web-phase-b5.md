- **The Review and Keys views move to `oml-web`** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d3, d5, d7 (b); ADR-0045 d9, d11, d13; ADR-0055 d10; issue #189). The Review view is at `/web/review` and `/web/admin/review`: review next and the verdict, and on the admin page the queue of held memories per workarea and bulk review with its confirmation. The Keys view is at `/web/keys`, where a person issues a key or a connector key, mints a connect code and cuts a key off, and at `/web/admin/keys`, where an admin lists one person's keys and cuts one off. Every act runs through the documented API operation as the person's session key, and a form sent twice runs once. A key's value or a connect code is shown once, on the page the act lands on, carried there in a sealed cookie that page clears, never in an address or a log line. A memory served for review now carries `search_text`, what a derived format's claim will be found by. The server answers `GET /web` (signed in), `?view=review`, `?view=keys`, and the admin page's `?view=review`, `?view=held` and `?view=queue` with a redirect to the new paths, and an old form's review or key act with a redirect to its view, running nothing. Caddy, both compose routers and the chart's `web.ingressPaths` route the four paths; upgrading a deployment means adding them to the proxy ([Run the web console](operations/web-console.md)).
