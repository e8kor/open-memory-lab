- **The Workareas view moves to `oml-web`, with the first acts it runs** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d3, d5, d7 (b), d8; ADR-0045 d28; issue #189). The view is at `/web/workareas` on the user page and `/web/admin/workareas` on the admin page, served by `oml-web` over the public HTTP API. Its dropdown offers what `GET /v2/workareas/{workarea}/offers` admits, Apply asks to confirm and names a refused act's refusal, and the confirmation's form proposes, ratifies or sets the mode through the documented operation as the person's session key, then lands back on the view. A confirmation sent twice runs once: its form carries a nonce, the act's `Idempotency-Key` is its digest with the session token, and the transition, ratify and mode operations now replay a recorded outcome under the same key with `Idempotency-Replay: true`. The offers name each act not offered under `refused`, with the code and message its verb would answer. The server answers `GET /web?view=workarea` and `GET /web/admin?view=workarea` with a redirect to the new paths, and an old form's workarea act with a redirect to the view, running nothing; the Atlas panel's dropdown asks the new path. Creating a workarea stays the server's act. Caddy, both compose routers and the chart's `web.ingressPaths` route both paths; upgrading a deployment means adding them to the proxy ([Run the web console](operations/web-console.md)).
