- **Memory can be read as it was at a past instant, under today's access** ([ADR-0059](adr/ADR-0059-a-memory-states-when-it-is-true-recall-hides-what-has-ended-and-searches-the-dates-a-query-names-without-a-model.md), amended 2026-11-11, d14–d21, building ADR-0036 d3 in part; issue #192). `as_of`, an RFC 3339 instant, rides `GET /v1/memories/{artifact_id}`, the scoped listing `GET /v1/memories` and `POST /v1/memories/recall`, and `oml_read` takes it in every mode. It is transaction time, apart from recall's `now` and the listing's `since` and `until`. Two facts come from the instant, rule `oml-asof/1`: a version recorded after it does not exist, and a claim's tip is the version approved latest by then; everything else is today's, so grants and denials, state, retirement and expiry are read now, a version erased or demoted today is served at no instant with no earlier version standing in, and held rows follow today's rules. Recall at an instant runs the same pipelines over the scope at the instant, a postings pipeline read by `bm25`'s scan, reads its scope alone and offers no `did_you_mean`. Its cost grows with claims' version chains: the median paired ratio to today's recall is 2.0 over two-version chains on CI, which CI gates at 3, and 3.2 over five-version chains. An instant after the server's clock, a date, or `as_of` with `own`, `with_own`, `author`, `tip` or wider `sources` is `request.validation` naming the field; no answer echoes the instant. Migration 0041 adds `memories_tip_moves`, the index the tip probe reads under row security; it runs outside a transaction and builds each tenant's partition in its own, so an insert waits only for its own tenant's build, an update planned through the parent can wait behind one running build, reads never wait, and a retry resumes. `GET /v2/search` counts promoted versions with no `promoted_at` as `valid_time.untimed`, and `oml doctor` warns when there are any, since an as-of read never serves them. `GET /v1/memories/{artifact_id}` now refuses any query parameter but `as_of` with `request.validation`, where it ignored them before. The laws run on the in-memory double and on PostgreSQL, with HTTP and MCP tests and a timing pair at 10,000 and 100,000 rows. The API's "proposed ADR-0059" markers are removed, since ADR-0059 is accepted. The SDKs' `read` helpers, openapi, the MCP tool and the generated references are updated.
