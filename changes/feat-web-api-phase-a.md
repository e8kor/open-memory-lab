- **The public API serves what the web console needs, and a person's session reaches it only through `oml-web`** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d2, d5, phase a; issue #188). A web session now carries one capacity credential per capacity its entry reaches, `omls_` and the base62 of HMAC-SHA256 keyed by the session token; only their SHA-256 is stored, in `web_session_credentials` (migration 0039), and they end with the session. The API accepts one as the person's session key only with `oml-web`'s client identity, the `OML-Web-Client` secret set as `web.client_secret` on both processes, and never on `/mcp` or beside a forwarded client certificate (`auth.invalid`, `details.reason: session_outside_web`). `web.client_ca` stops the server at start: mutual TLS needs a TLS listener the server does not have yet. `/readyz` names the identity as `web_client`, and `oml doctor` warns `no web client identity set` when the web pages are on without one. Ten operations are new: `GET /v2/keys`, `GET /v2/review/queue`, `GET /v2/workareas/{workarea}/offers`, `POST /v2/web/session/end`, `GET /v2/web/export`, `POST /v2/web/deletion-requests`, and, for the admin key role, `POST /v2/web/users/{user}/capacities`, `…/quota`, `…/disable` and `…/deletion/close`. A person's own acts answer `access.verb_ceiling` `session_key_only` to any key but their web session key, an agent's key naming them included. Six operations change: `GET /v1/memories` takes `with_own` and `author`, the tree takes `counts`, the admin search takes `origin_kind` and `author`, `GET /v2/review/held` takes `ids`, the allowlist's add and remove take `keep_an_admin`, and `GET /v2/whoami` serves `person`. Each is a use case the pages already call, served behind its operation; the pages keep calling them until phase b moves them to `oml-web`. `openapi-designed.yaml` loses `listKeys` and `reviewQueue`, and the Python and TypeScript SDKs are regenerated.
