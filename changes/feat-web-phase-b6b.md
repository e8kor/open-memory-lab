- **Start, setup, the admin overview and the users page move to `oml-web`** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d5, d7 (b); ADR-0045 d10, d13; ADR-0068 d5, d6, d8, d10; issue #189). The onboarding page is at `/web/start` with its status poll and export, the setup view at `/web/setup`, the allowlist and the review and curation grants at `/web/admin/people`, and quotas, disabling and deletion requests at `/web/admin/users`. Every act runs through the documented API operation as the person's web key or the admin's admin key, and a form sent twice runs once: adding or removing an address now replays at the API too. A credential issued on the Start page is shown once on the page the act lands on, through a sealed cookie, never in an address. Removing an address, disabling a person and closing a deletion request each show a confirmation before anything is recorded. `GET /v2/whoami?start=true` names the onboarding status. The server answers `GET /web?view=setup` and `GET /web/admin` with a redirect to the new paths, and an old form's act with a redirect, running nothing; its only pages are now sign-in, the sign-up terms page and sign-out. Caddy, both compose routers and the chart's `web.ingressPaths` route the six paths; upgrading a deployment means adding them to the proxy ([Run the web console](operations/web-console.md)).
