**Web console, one memory looks the same on every surface.** On the person's side the card names the author by the principal the read serves and gives no kind: the API serves `provenance: "agent"` for every key, so the kind was a guess, and the same memory read "person" on Memories and "agent" in Review. The admin side, whose read serves `held_by`, keeps the kind after the key's name. An opened row lists the same facts in the same order and words on Memories, both Reviews and the one-memory page (the Memories row keeps its timeline above them, design notes row 12), and the approval line has one wording on both sides: the admin's says when, from its verdicts, and leaves out the kind its read does not serve. The Memories list no longer reads the person's key list; only a text search that names an author does.

**Web console, a nested shared workarea's reference.** The console named every workarea under a top label as if that label were a person's root, so `universe.platform.oncall` read `platform.oncall`, a name no field resolves: Review's Waiting table, its cards' links and verdict line, its `?workarea=` filter, the admin card's link and the admin One memory page's policy line all missed it. Each page now knows which top labels are user roots from what it reads: the tree read's `user_root` marks, the person's own root, and, for a top label neither names, one read of that label's node (`GET /v2/workareas/{top}/tree?limit=1`), which a page whose rows sit in the person's root and `universe` never makes. `oncall` is `oncall` on both sides.

**Web console, the admin Review page.** "Open to judge" and its `judge` act are the person's Review page's alone, as the ADR-0055 d10 amendment and ADR-0070 d7 (b) say: the admin page draws no such link and no judge form for `?memory=`, and refuses `action=judge` as an action it does not define.
