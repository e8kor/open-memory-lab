**The workarea lifecycle, proposed.** Five records proposed together give workareas a development lifecycle, and the [workarea lifecycle review](https://github.com/e8kor/open-memory-lab/blob/main/design/workarea-lifecycle.md) walks it stage by stage with the operator's decisions of 2026-11-14. ADR-0085: a workarea publishes immutable releases that one person proposes and another ratifies; each key binds to the tip, the latest release or a pinned one; a release-bound key never sees held items; a release may be cut while the workarea is in progress; admins keep erasure only. ADR-0086: tests are reviewed claims the server runs under the caller's key, and a release is published only through ordered gates. ADR-0087: an impact report shows, under the caller's own reads, what a release changes for the workareas that receive it. ADR-0084: a workarea moves between servers as a signed, encrypted bundle whose import lands held in an in-progress workarea. ADR-0088, deferred: verdicts from a pinned trusted source server.
