Three leftovers of the CLI's re-verification closed (#332). `oml doctor`'s scan line carries the admin key's failed rescan read as the usage and approval lines do: `warn scan_held_unrescanned, scan_rescan_due: not read (<reason>)`, no longer `an admin key reads them`, which that key is. In a build with `lake-sync`, a tip anchor hash of `sha256:ab`, an empty one or one with a multi-byte character no longer panics `oml sync --adapter delta`: the changed note takes the first four characters it has. `promoted_unapproved`, and so doctor's `approval_unmatched`, no longer counts an unapproved retirement tip, since recall serves no retirement version; both stores and the port law agree, and the upgrade page says so.
