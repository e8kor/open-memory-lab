**A version records its author's person at its write.** Since migration 0061 every version records, when it is written, the person its author key acts for (`memories.author_person`): a session key's person, the user root a user key names or a linked tenant key is linked to, or none. The `same_user` mark on an approval, R2 by person (the verdict refused outside the person's root, and the row left off that person's review listing and queue) and a person's session withdrawal read that record, so an admin unlinking a key between a write and its verdict no longer clears the mark or lifts the refusal. The migration gives every earlier version the person its author key resolves to when it runs ([ADR-0085](adr/ADR-0085-a-workspace-publishes-immutable-releases-that-one-person-cuts-and-another-ratifies-and-each-key-binds-to-the-tip-the-latest-release-or-a-pinned-one.md) d16, amended 2026-11-18; #448).

**The lake writer stops naming chrono.** `oml-lake` and `oml-lakewriter` keep their own timestamps in `jiff`, as RUSTSEC-2026-0543 recommends, read PostgreSQL's timestamps as Unix microseconds, and drop sqlx's `chrono` feature. chrono stays in the graph through arrow and deltalake only, so `deny.toml` no longer ignores the advisory: `cargo deny` reports a transitive unmaintained crate and does not fail. `oml-lakewriter run --retention-hours` now refuses a negative value (#445).

**Search finds every kind of claim, and a read without a query is the catalog.** Recall's `kinds` takes all ten kinds. A recall that names none ranks memories, derived facts, tests, the skills the scope offers and the guardrails that apply there in one list, each hit marked with its kind; a skill hit names its prompt and resource and serves its description, never its body, and a guardrail hit shows a rule already in force without binding anything. `kinds` decides whether the steering list is served (`steering: "not_requested"` otherwise), and `search.matched_by_kind` counts each kind's candidates before the `k` cut. `oml_read` without a query, `GET /v1/memories` without `own` and `oml read` without `--query` now answer the catalog: every kind the key reads, filtered by `kinds`, `prefix` and `state`, entries without text unless `include_text`, and per-kind counts on the first page, capped by the new `catalog.count_cap` (10,000). On MCP `own` now defaults to `false`: an agent asks for its own work with `own: true`. Migration 0062 gives every hit kind search postings and adds the catalog's index ([ADR-0092](adr/ADR-0092-search-filters-by-every-claim-kind-and-ranks-skills-and-guardrails-as-data-and-a-read-without-a-query-is-the-catalog-of-what-a-key-reads.md), amended 2026-11-18 with the build's readings; #443).
