**Web console.** The Start page and the Keys page draw a "Your usage" card, and the users page draws the meters as columns (ADR-0071 d6, #321). The five meters `person` on `GET /v2/whoami` and each row of `GET /v2/web/users` carry are shown with their count, their limit where one holds, and a mark at 80% of the limit and at the limit: memories, text stored, writes this month, keys and connections, with the request rate beside them on the card. The users page draws no mark for a person the limits do not hold for, one outside the sign-up tenant. A person whom no limit is read for gets no card, and a meter an older API does not serve is left out, never shown as zero. The profile's name, the month and the recall count are not on those fields and are not shown, so a console session needs a route or fields for them (ADR-0071 d6, amended). The Keys page reads the person beside its key list in the same round; a failed read marks the card unavailable and the keys still draw. The Rust SDK's `Usage` and `Limits` carry `text_bytes`, `writes` and `writes_per_month`, and `Client::whoami_person` asks for the person block.
