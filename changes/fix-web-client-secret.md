- **The web client secret is stored in an owner-only file or the environment, refused when weak, and rotated without a refused page** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d2; issues #230, #242). The server and `oml-web` read `web.client_secret` from the environment or from the file `web.client_secret_file` names, which on Unix must be readable by its owner alone, as systemd's `LoadCredential=` gives. Both refuse to start with a secret shorter than 32 characters, with fewer than 8 distinct characters, or with a space or line ending, naming the setting and never the value. To rotate, set the new secret on the server with the old one as `web.client_secret_previous` and an instant at most 7 days ahead as `web.client_secret_previous_until`, restart the server, then `oml-web`, then unset the two; the server accepts the old secret until the instant and never after, and logs a warning at each start while it is set. `oml-web --doctor` now says whether the server accepts its secret, which `/readyz` cannot. The Helm chart reads the two rotation keys from the web client Secret, each optional, for the server alone, keeps keys an operator adds to the Secret it generates, and `check_chart.py` holds that no secret is a literal value and that `web.clientSecret.existingSecret` renders no Secret of the chart's own. `check_release.py` also refuses a release workflow that sets `OML_CARGO_FEATURES`. Mutual TLS remains unbuilt and documented as the alternative ([Run the web console](operations/web-console.md#store-the-client-secret)).
