**Skills are offered as MCP prompts and resources.** A skill is written by any writer, over `oml_write` with `kind: "skill"` and its `skill` object or over `POST /v1/memories`, and every version waits for a person's approval. `GET /v1/skills` serves the skills offered at the key's scope, 50 a page with a set digest and no bodies: the scope node's own, its readable ancestors' under `guardrail_scope: ancestors`, and inside an in-progress workspace the subtree below it, the nearer workspace winning a shared name and naming what it `overrides`. The key's own held skills and an in-progress workspace's held skills are offered marked `unreviewed`, a held edit of an approved skill, and a held skill whose name another offered workspace holds approved, as `<name>-unreviewed`, at most 50 held at once. The MCP server lists the guardrails prompt and then each offered skill on `prompts/list`, answers `prompts/get` with a header naming the workspace, version and approval, then the body and the input, and serves each skill at `oml://workspace/<workspace>/skill/<name>` through `resources/list`, `resources/read` and `resources/templates/list`; any name or URI not offered answers one error. `oml skills list` prints the set, the session-start hook adds an index of up to 20 skills, the tool-call hook asks before a file is written under `.claude/skills/`, and `oml doctor` names a server without skills, a shadowed name and skills kept on disk ([ADR-0080](adr/ADR-0080-a-skill-is-a-reviewed-claim-the-mcp-server-lists-as-a-prompt-and-serves-as-a-resource-loaded-live-and-never-copied.md) d1 to d15, with the build's readings of 2026-11-17 and 2026-11-18; #403, #404, #408). The store-call timing series `instruction_rows` is now labelled by kind, `instruction_rows.guardrail` and `instruction_rows.skill`; a dashboard on the old label reads neither.
