**The v0.8.6 review round's server fixes.** Migration 0077 runs 0070's backfills again under each tenant's row security. Before it, a tenant that had two admin persons stayed `sole_admin`, and admin entries accepted before the upgrade had no `admin_since`. At the first start the server now converts every admin key `used_by: service` to a `maintenance` key (`key.converted`, `cause: upgrade`). A conversion lifts an unlinked suspension in its own commit, so a key the start suspended can still convert itself, and a key whose link waits on its person is not swept (the operator's decision D27). Several acts that took effect at once now wait on a second admin person: the first curation designation, a quota raise and the decline of an accepted `sole_admin` flag, which is now an un-flag against that admin. A raise applies and declines only the limit it sent. An unlinked admin key is suspended until a link is accepted. An admin flag never moves to another user in one act. An empty reason is no reason. A contest restores the entry accepted, and the target contains the initiator from the contest-only sign-in. An admin grant into an in-progress subtree that would wait on a second admin person is refused `in_progress_subtree` until the subtree's reviewer confirmation is built. A completed recovery revokes every live admin key. A sign-in row the server could not write holds the completion and is written again. One refused recipient stops no notice email. A maintenance key reads the whole rescan window. Acts taken at once under `sole_admin` leave To do (D30). A public node's private ancestors show as `…`, never their names (D28, [ADR-0098](adr/ADR-0098-a-protected-or-frozen-workspace-can-be-marked-public-and-then-every-reading-key-in-the-tenant-reads-its-approved-items.md)). [ADR-0097](adr/ADR-0097-every-admin-act-is-one-journalled-record-narrowing-takes-effect-at-once-widening-waits-on-a-second-admin-person-and-every-admin-key-belongs-to-a-person.md) records D27, D29 and D30, with a note on the round's deferrals and readings for the operator to confirm.
