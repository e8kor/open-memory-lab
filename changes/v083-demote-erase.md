**Demotion and erasure, the admin fix's two acts.** A demotion stops serving any approved version and keeps its bytes. When the version was the tip, the latest earlier approved version that is not demoted is served again. An as-of read skips a demoted version at every instant and serves the version below it; the journal still records what was served ([ADR-0059](adr/ADR-0059-a-memory-states-when-it-is-true-recall-hides-what-has-ended-and-searches-the-dates-a-query-names-without-a-model.md) d22). An erasure takes every version of a claim. In one transaction it empties each version's text and the search rows derived from it, erases its search telemetry and destroys its lake data key, and keeps the digest, the title, a skill's name and description, and the attribution. PostgreSQL's copies in backups last until the backup window ends ([ADR-0005](adr/ADR-0005-erasure-by-crypto-shredding.md) d2, d4). Both are journalled as `lifecycle.demote` and `lifecycle.erase`, and the lake writer folds them. No route reaches them yet: the admin fix that takes them is designed ([ADR-0089](adr/ADR-0089-an-admin-fixes-a-production-workspace-at-once-by-a-marked-break-glass-act-that-a-person-confirms-or-reverts-afterwards.md) d16; #454, #455). Migration 0056 lets the server destroy a data key without reading one. Migration 0057 adds a trigger so no role re-keys a destroyed key, moves a destruction's time, or writes a new key into a live row without a new key-encryption key. A demotion that serves an earlier version again gives it back the end it had before the supersession (migration 0058). A retirement or a vocabulary term is not demoted (`lifecycle.demote_kind_unsupported`). `oml doctor` warns of held versions that no verdict can approve because their target is no longer the approved tip, and of erased versions whose data key is still live.
