**Design: a person builds a key in the console, and the admin console reads and limits one key.** [ADR-0096](adr/ADR-0096-a-person-builds-a-key-in-the-console-with-grants-inside-the-own-root-and-a-rate-and-the-admin-reads-one-key-and-sets-its-limits.md), accepted design of 2026-11-24, decided by the operator for v0.8.5 and not built. A person's web session issues a key with grants of its choosing inside the person's own root (node or subtree, with denials), a default workspace, a guardrail scope, a request rate and the role `submitter`, reversing the rate half of ADR-0079's answer 3 and the console half of ADR-0093 d6; the administration console reads one key, sets its expiry and rate, and denies it on any workspace, and still issues none (ADR-0070 d2). The Fix form becomes a tab of the admin workspace page until releases exist (ADR-0083 d9). A person's web session reads and lists the imports of every key of the person (ADR-0084 d15). To do gains a group for brief proposals; the key list serves each grant's coverage; the usage card gains the profile, the month, recalls and the `workspaces` meter; the console sends an expiry date as the end of the next UTC day. The import-review group, recording a key's last use (#131), the admin key builder, an issuance dry run and inline scripts are deferred. Amendment notes dated 2026-11-24 are added to ADR-0070, ADR-0079, ADR-0083, ADR-0084 and ADR-0093.
