- **The Guardrails view is the first page `oml-web` serves, over the public HTTP API** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d1, d3, d4, d7 (b), d8, d9; issue #189). `oml-web` now reads the session cookie, derives the person's capacity credential from it, checks the session with `GET /v2/whoami`, and sends a person with no session to sign in. It refuses a form from another origin by the server's own rule, and one without the session's CSRF token. Its policy names the one stylesheet by its digest. Each API call carries the page's request id as its correlation and `<page id>.<n>` as its own, under a 10-second timeout over one pool of kept-alive connections. The page's log line names the acting key and those ids. An API refusal becomes the page the server would show, naming the request id, and a failed workarea list leaves the Guardrails view without its selector rather than failing it. `GET /web?view=guardrails` moves to `oml-web`: the server answers it as not found, and the proxy routes it to `oml-web` ([Run the web console](operations/web-console.md)). `oml-sdk` (`sdks/rust`) is the hand-written Rust client `oml-web` calls; `check_contract_sync.py` holds its operation table to `openapi.yaml` by operation id, method, path and field names. `oml-page` now holds the pages' stylesheet, marks and chrome, with the same-origin rule both processes call (#230), and `oml-web-credential` the session token's derivations, which `oml-domain` re-exports. `oml quickstart`, the compose file, the Helm chart and the release archives do not start or ship `oml-web` yet. ADR-0070 records where this change reads d1, d3, d4, d8 and d9 differently.
