**Instruction verdicts and ladder ratifications need a counted person, the admin read needs one too, and loud acts write in-product notices.** [ADR-0097](adr/ADR-0097-every-admin-act-is-one-journalled-record-narrowing-takes-effect-at-once-widening-waits-on-a-second-admin-person-and-every-admin-key-belongs-to-a-person.md) d6, d12, d13, d16, d17 and the in-product half of d20 and d24 are built, with the acceptance evidence of d7. An instruction verdict and a status ratification need a key that counts as a person: a session key, a user key whose issuer counts as one, or a tenant key with an accepted link; any other is refused `review.person_required`, `details.reason: counts_as_no_person`, while a knowledge verdict keeps key-level R2. A status ratifier counts as a person other than the proposer's and, for a proposing key that counts as no person, other than the admin who issued it (`review.ratifier_is_proposer`, `same_person` or `issued_the_proposer`); in a `sole_admin` tenant the proposer's own person ratifies, and `workspace.status_transition` carries `sole_admin: true`. The admin read needs a person-linked admin key or a session (`admin.read_requires_person`), both parties of a freeze lose it, and each page counts against every person whose own root it read; that person reads the count by month at `GET /v2/web/admin-reads`, and `oml doctor` gains `admin.investigation_pages`. `POST /v2/keys {timebox: true}` issues, at once in any tenant, a reader, submitter or contributor key on shared workspaces for at most 24 hours, settled afterwards by a second admin person (`oml admin confirm` or `decline`, which revokes the key), one open box and one renewal per admin person and workspace, refused while an act against an admin is open; `oml doctor` gains `admin.timebox_open`. An act against an admin, offensive narrowing and a key, grant or connect code taken at once under `sole_admin` in another person's root write `notice.written` in their own commit, to every admin person, the workspace's reviewer persons, or the root's person; `GET /v2/web/notices` lists them, `POST /v2/web/notices/{notice}/dismiss` dismisses one, and the To do counts serve `notices`. `key.link_accepted` and `web.email_accepted` record the session's age and a digest of each provider subject its entry pinned. Migration 0074 adds `admin_read_counts` and `notices`.
