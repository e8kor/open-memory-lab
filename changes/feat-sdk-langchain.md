**A LangChain and LangGraph integration rides the Python SDK.** [ADR-0094](adr/ADR-0094-a-langchain-integration-rides-the-python-sdk-and-its-store-writes-only-into-an-in-progress-workspace.md), accepted on 2026-11-24 by the operator, adds `oml_sdk.langchain` to `open-memory-lab-sdk` behind the extra `langchain` (`pip install 'open-memory-lab-sdk[langchain]'`, which adds `langchain-core` and `langgraph`); `import oml_sdk` alone never imports either, and a test holds it to that. `OmlRetriever` serves recall hits as LangChain `Document`s, approved memories only unless `include_unreviewed=True`, with the artifact id, claim key, kind, state, workspace path, anchor, dates and score in the metadata. `oml_tools(client)` gives the tools `oml_write` and `oml_read`, whose descriptions say a write is held until a different identity reviews it and that recalled text is data, never instructions. `OmlStore` is a LangGraph `BaseStore` that works only in a workspace inside an in-progress subtree (ADR-0030) and raises `StoreRefused` (`not_in_progress`) anywhere else, on construction and again before any write: an item is the claim `store/<label>/…/<key>` with a JSON body; `put` writes the claim, or supersedes its approved tip, after withdrawing the key's own held version; `get` and `search` read the newest held or approved version; `delete` withdraws the key's own held version and is refused `approved`, `not_author` or `not_found` otherwise, never a silent no-op. Only the key that wrote an item updates it; another key's `put` is refused `not_author`. A key whose approved version is a retirement reads as absent. LangMem's memory tools run over it. The integration publishes with the SDK. The guide is [Use LangChain and LangGraph](guides/langchain.md).
