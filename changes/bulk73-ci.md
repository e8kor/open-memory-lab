The weekly dependency pass runs `scripts/check_action_updates.py`, which reports a pinned action with a newer tag of its major and prints a newer major without failing; [CI and toolchain](contributing/ci-and-toolchain.md#pinned-actions) says how to change a pin. The SDK publish lint now also refuses a step-level `if:` in the two publish jobs, an upload before the checksum step, `npm --flag publish`, `npx npm publish`, `pnpm publish` and `yarn publish`, `packages-dir`, `repository-url` and `password` on the PyPI action, and a checkout of anything but the tag; the PyPI job uploads the default `dist/`, which holds only the two checked files (#184). Both SDK packages are named `open-memory-lab-sdk` on PyPI and npm, the operator's choice of 2026-11-12; the Python import name stays `oml_sdk`. Publishing stays off until the operator sets `PUBLISH_SDKS`. [Releasing](contributing/releasing.md#publishing-the-sdks) says that `True` and `TRUE` turn it on as `true` does, and lists what a shared server needs before a release that contains ADR-0076, a new scanner rule set or a migration that rewrites `memories`. The [settings page](operations/configuration.md#limits-counted-per-process) states that the per-key request rate (120 a minute) and the per-address sign-up count (5 an hour) are counted per process, so N processes admit up to N times each; the thirty-day measurement of the defaults is still open (#164). The pin lint parses each workflow as YAML, so a `uses` key in a flow mapping, a quoted key, a value on the next line, an anchor or a merged mapping is read, and a sub-path of an action at another commit is the same action at two commits.
