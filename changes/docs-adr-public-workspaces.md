**Design: a protected or frozen workspace can be marked public.** [ADR-0098](adr/ADR-0098-a-protected-or-frozen-workspace-can-be-marked-public-and-then-every-reading-key-in-the-tenant-reads-its-approved-items.md), proposed for v0.8.6 and not built. One `public` flag on a `protected` or `frozen` node outside every user root lets every reader, contributor and reviewer key of the tenant, user keys included, read that node's approved items, with their authorship, without a grant of its own; a submitter key still recalls nothing. The flag covers the node alone and children are not inherited; no default recall gains it, so a key names it as the scope, lists it in `sources` or reaches it by `wide`. Denials still win, ranking is unchanged, and it never crosses tenants or serves a reader without a key. Setting it is an admin act of class widening under ADR-0097, waiting on a second admin person, and clearing it is narrowing, at once.
