- **The server no longer redirects the web console's addresses of v0.6** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d7 (b), d7 (d), "The old URLs deleted"; issue #283). The operator decided to delete the redirects v0.7.0 kept for one release. The server's web routes are now the sign-in context's alone: `GET /web` (the sign-in page, and for a signed-in browser the way on to the Keys view), sign-out at `POST /web`, `/web/sign-in`, the provider callback and `POST /web/sign-up`. `GET` and `POST /web/admin` are gone, and `docs/api/openapi.yaml` and the generated SDKs drop them (`admin_page`, `admin_page_act` and their models in the Python SDK, their types in the TypeScript schema; `user_page()` loses its `view` parameter, `UserPageView` is gone, and `UserPageActBodyAction` is `SIGN_OUT` alone). The user page's Administration tab now links the overview at `/web/admin/people`. Upgrade note: old bookmarks now 404. `GET /web?view=...` with a session, `GET /web/admin` and a path below it that `oml-web` does not serve answer not found, and a form cached from a v0.6 page that posts an act other than sign-out is refused and runs nothing; use the pages' own paths in [Run the web console](operations/web-console.md). No proxy change is needed: `/web` and `/web/admin` already fall through to the server.
