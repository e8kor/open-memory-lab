**A user's root takes memories from that user's keys only** ([ADR-0044](adr/ADR-0044-every-user-works-under-a-root-of-their-own-and-universe-serves-curated-claims-without-their-source.md) d16, a **proposed** amendment the operator has yet to accept; #329). A tenant writer key holding a subtree grant on `universe`, or any grant inside a user's root, could write claims into `universe.<user>`; with usage metering that moved a person's `memories` with no check against their ceiling. A new memory, a successor or a retirement there by a key that is not that user's is now refused `409 submission.user_root_refused`, on `POST /v1/memories`, on supersede and in every mode of `oml_write`, and journals nothing. The code is answered only where the key reads the workarea or the target; a key that reads neither keeps `access.not_found`. Reads, recall and review by tenant keys there are unchanged, except that a tenant reviewer no longer edits by proposal in a user's root. Nothing already written is touched: versions tenant keys wrote there before stay served, reviewable and under the accounting [ADR-0071](adr/ADR-0071-every-account-is-metered-by-counters-the-write-updates-in-its-own-transaction-and-named-quota-profiles-set-its-limits.md) d3 states, whose sentence now says no new write produces that case. `oml doctor` under a tenant writer key whose default workarea lies in a user's root warns and names the key to issue instead. Grants are unchanged, so `my_effective_verbs` still lists the write verbs for such a key. [errors](api/errors.md), `openapi.yaml`, [roles and keys](architecture/roles-and-keys.md) and [workareas](architecture/workareas.md) carry the rule, and both SDKs' generated layers the new code.
