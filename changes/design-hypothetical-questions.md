- **Proposed: each approved memory is indexed by the questions it answers** ([ADR-0075](adr/ADR-0075-each-approved-memory-is-indexed-by-the-questions-it-answers-generated-off-the-request-path-scanned-stored-with-their-generator-and-matched-only-by-an-opt-in-pipeline.md), for [#201](https://github.com/e8kor/open-memory-lab/issues/201)). When a version becomes served, a generator the operator configures writes up to five questions it answers, off the request path; nothing held, unreviewed or carrying a hold finding is expanded. A question is kept only if it is grounded in the memory's own words, specific and clean, and any scan finding drops it. Questions are stored per version with the model and prompt version that wrote them, every change to them is journalled, and they are indexed as a second field that the opt-in `bm25-questions` pipeline scores with the memory text by field-weighted BM25 (BM25F), with no model call at recall; a row without questions scores exactly what its own text earns, a hit names the question it matched, and a question is never served as memory text. The default stays `bm25-postings`. An offline phase 0 ([#235](https://github.com/e8kor/open-memory-lab/issues/235)), on a labelled set grown to at least 420 queries so the gain can be seen, decides whether the server work ([#236](https://github.com/e8kor/open-memory-lab/issues/236)–[#238](https://github.com/e8kor/open-memory-lab/issues/238)) is built, against gates on that set, LoCoMo and BEIR. Decided, not built.
