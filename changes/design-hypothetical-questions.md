- **Proposed: each approved memory is indexed by the questions it answers** ([ADR-0075](adr/ADR-0075-each-approved-memory-is-indexed-by-the-questions-it-answers-generated-off-the-request-path-scanned-stored-with-their-generator-and-matched-only-by-an-opt-in-pipeline.md), for [#201](https://github.com/e8kor/open-memory-lab/issues/201)). When a version becomes served, a generator the operator configures writes up to five questions it answers, off the request path; nothing held, unreviewed or carrying a hold finding is expanded. Each question is filtered and scanned, and any finding drops it. Questions are stored per version with the model and prompt version that wrote them, indexed as BM25 postings in a field of their own, and matched only by the opt-in `bm25-questions` pipeline, which makes no model call at recall; a hit names the question it matched, and a question is never served as memory text. The default stays `bm25-postings`. An offline phase 0 ([#235](https://github.com/e8kor/open-memory-lab/issues/235)) decides whether the server work ([#236](https://github.com/e8kor/open-memory-lab/issues/236)–[#238](https://github.com/e8kor/open-memory-lab/issues/238)) is built, against gates on the synthetic recall set, LoCoMo and BEIR. Decided, not built.
