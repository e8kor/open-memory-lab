**Documents: one passage rule, `oml sync --adapter document`, and the passage cap.** A new leaf crate, `oml-passage`, holds the passage rule of [ADR-0081](adr/ADR-0081-a-document-is-a-reviewed-markdown-or-text-claim-that-recall-searches-by-passage-and-the-mcp-server-serves-as-a-resource.md) d3 with no I/O. It covers headings of level 1 to 4, sections over 40 lines cut at blank lines, and front matter and HTML comments skipped. The server and `oml-cli` both link it, and a shared vector file holds them to one cut. A heading's slug reads a link by its text on both sides, so a document titled `[Guide](https://x.y)` keys as `doc/guide` (ADR-0081 d2, amended). A document whose text cuts into more than 4,096 passages is refused with `request.validation`, `details.field: /body`, `details.reason: too_many_passages`. `oml sync --adapter document` writes one `document` claim per `.md` or `.txt` file, keyed `doc/` and the path without its extension, and anchored to the whole file. A path whose key falls outside the document key grammar is reported unreadable. A run over a source that another adapter loaded is refused, naming both adapters and the claims it would leave (ADR-0081 d7). The build's readings R1 to R6 are recorded in ADR-0081 for the operator's batch (#405, #406).
