**The console builds keys, reads one key for the admin, and adds the Fix tab, the import pages and the brief group (v0.8.5).** [ADR-0096](adr/ADR-0096-a-person-builds-a-key-in-the-console-with-grants-inside-the-own-root-and-a-rate-and-the-admin-reads-one-key-and-sets-its-limits.md) is built. A person's web session issues a contributor, reader or submitter key with grants inside the person's root, a default workspace, a guardrail scope, an expiry and a rate, at most 16 grants of 16 denials (`too_many`); `GET /v2/keys/{key}` resolves the session caller, so `<user>-admin` reads one key, sets its limits once per form (the `Idempotency-Key` replays) and denies it on any workspace of the tenant, and still issues none. `GET /v2/keys` serves each grant's `covers`; `GET /v2/imports` lists the imports of every key of the person, and `GET /v2/imports/{id}` admits `<user>-web` for them (migration 0068 indexes imports by importing key); `GET /v2/review/briefs` lists the brief edges `<user>-review` may ratify, `/v2/todo/counts` gains `briefs` and `/v2/admin/todo/counts` `alerts`; `POST /v2/edges/{id}/ratify` takes a session caller; `whoami`'s person and each users row gain `profile`, `period` and `usage.recalls`. The console gains the key builder at `/web/keys/new`, the Keys list's coverage mark and an expiry read as the next UTC day's end, the admin one-key page with its limits and deny forms, the admin workspace page's Fix tab posting to `/web/admin/fixes`, the import hand-off and lists at `/web/workspaces/import`, To do's brief group with Ratify, and the admin To do's fixes and alerts. The workspace page's brief section, Propose for brief, the status proposal on the workspace page, the export page and the personal fix confirmation page are not built here; the ADR's build notes say why.
