**Fix: the plugin's guardrail check no longer freezes a session when it fails or stalls (#519).** On 2026-11-25 the PreToolUse check timed out on a loaded host and, under `onFailure: "block"`, refused every tool call of a session and its subagents. The entry now sets no `onFailure`, so a timeout lets the call through; a verb that fails prints one stderr line naming the cause and the bypass and exits 1, a non-blocking error, and the command ends `|| exit 1`, so no exit code blocks a call. `OML_HOOK_DISABLE=1`, set before a session starts, skips the check without running `oml`, and `oml doctor` prints `warn guardrail_check_off` while it is set. A cache that does not parse still denies every call, and the matcher is unchanged. [ADR-0037](adr/ADR-0037-a-guardrail-is-a-reviewed-rule-loaded-at-session-start-and-checked-at-the-tool-call.md) d9 gains a dated amendment of 2026-11-26, proposed and awaiting the operator's acceptance; ADR-0064's hook table, the plugin README, the Claude Code guide and the configuration page say the same.
