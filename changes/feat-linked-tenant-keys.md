**A person's tenant key can be linked to their sign-in, and the console acts with it.** An admin links a live tenant bearer key `used_by: person` to a person with `POST /v2/keys/{key}/link {user}` (`oml keys link <key> --user <user>`), journalled as `key.linked_person`, and ends the link with `POST /v2/keys/{key}/unlink` (`key.unlinked_person`). A linked key acts for its person: the same-person rule and `same_user` read the link. The console offers each linked key for acts in the workspaces it grants and names the key on the page. It sends `OML-Acting-Key` beside the session's capacity credential, and the lead honours the header only from `oml-web`, with a capacity credential, never on `/mcp`, and only for a live key of the tenant linked to the session's own user and used by a person; anything else is `auth.invalid`, reason `acting_key_not_linked`.
