**Sign-in.** A Google ID token whose `aud` array names any audience besides the configured client id is now refused as `provider_refused`, the reason a token for another client already gets; a string `aud` and a one-element array naming the client id sign in as before. This closes the one difference from OpenID Connect Core 1.0 §3.1.3.7 item 3 that [the two provider points](adr/ADR-0045-people-sign-in-to-a-user-page-and-an-admin-page-on-the-servers-own-origin.md#the-two-provider-points-as-checked-against-the-providers-documentation-2026-11-13-119) recorded, which rejects a token "if it contains additional audiences not trusted by the Client" ([ADR-0045](adr/ADR-0045-people-sign-in-to-a-user-page-and-an-admin-page-on-the-servers-own-origin.md) d4, #366).
