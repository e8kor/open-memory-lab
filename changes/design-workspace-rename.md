**One breaking rename in v0.8.0: workspaces, reviewer, protected, frozen, used_by.** The operator asked on 2026-11-14 for the rename of workareas on every surface ("lets do renaming of workareas to workspaces across whole project, sourcecode, documents, web, landing, everything"), added the role ("Use 'reviewer' instead"; "Yes, same ADR and v0.8.0") and then the ladder and the key holder ("Fold into v0.8.0"), and accepted [ADR-0091](adr/ADR-0091-workareas-become-workspaces-and-the-dreamer-role-becomes-reviewer-on-every-surface-in-one-cut-and-the-journals-former-names-are-read-through-one-map.md) the same day. `workspace` replaces `workarea` in the HTTP API, MCP (`oml_workspace`), the CLI (`oml workspaces`), the environment (`OML_CHAT_WORKSPACE`, `OML_WORKSPACE_NAME`), error codes, the metric, the request log, spans, the console's routes, the schema, the lake columns and the SDKs; the role `dreamer` becomes `reviewer` ("curator" was rejected because it already names three things); the statuses `committed` and `validated` become `protected` and `frozen`; and a key's `held_by` becomes `used_by`, with `human` now `person`. The cut is pure: a retired name is unknown input, so clients upgrade before the server. The server writes the new names from the release on; signed events keep the former ones and every reader (replay, the lake twin's `fold_of`, `oml verify`, `oml events`) reads them through one map, which keeps ADR-0090's rebuild equality. A design record's number is its key; the register lists renamed records' former file names, and nothing redirects. The lifecycle review's display names (approve, take, the drafts-visibility toggle, development and production rules) change copy only. ADR-0091 amends ADR-0009, ADR-0010, ADR-0018, ADR-0025, ADR-0026, ADR-0037, ADR-0077 and ADR-0090. Decided, not built.
