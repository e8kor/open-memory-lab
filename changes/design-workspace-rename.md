**Workareas become workspaces and the dreamer role becomes reviewer (proposed).** The operator asked on 2026-11-14 for the rename on every surface ("lets do renaming of workareas to workspaces across whole project, sourcecode, documents, web, landing, everything") and decided a hard cut in v0.8.0. Proposed [ADR-0091](adr/ADR-0091-workareas-become-workspaces-and-the-dreamer-role-becomes-reviewer-on-every-surface-in-one-cut-and-the-journals-former-names-are-read-through-one-map.md) records it: `workspace` replaces `workarea` in the HTTP API, MCP (`oml_workspace`), the CLI (`oml workspaces`), the environment (`OML_CHAT_WORKSPACE`, `OML_WORKSPACE_NAME`), error codes, the metric, the request log, spans, the console's routes, the schema and the SDKs, with no aliases, and a retired name is refused by name rather than ignored. The server writes `workspace.*` events from the release on; signed `workarea.*` events stay as written and every reader (replay, the lake twin's `fold_of`, `oml verify`, `oml events`) reads them through one map, which keeps ADR-0090's rebuild equality. A design record's number is its key, and a renamed record's former file name is kept in the register's redirect table. The operator added the role rename the same day ("Use 'reviewer' instead"; "Yes, same ADR and v0.8.0"): `dreamer` becomes `reviewer` under the same rules, grants such as `dev:dreamer` become `dev:reviewer`, signed `role: "dreamer"` values are read as `reviewer`, and "curator" was rejected because it already names three things. It amends ADR-0010 d1 and d5, ADR-0018 d4, ADR-0026 d1 and d5, ADR-0037 d4 and ADR-0090 d12 and d14. Decided, not built.
