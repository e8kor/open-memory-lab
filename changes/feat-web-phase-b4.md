- **The Memories list and the Atlas move to `oml-web`, and creating a workarea becomes the Workareas view's act** ([ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md) d3, d5, d7 (b), d8; ADR-0045 d22–d32). The list is at `/web/memories` and `/web/admin/memories`, the Atlas at `/web/atlas` and `/web/admin/atlas`, and their JSON at `/web/data/memories` and `/web/admin/data/memories`, served by `oml-web` over the public HTTP API with the same rows, filters, keyset paging, treemap with no script and table twin as before; the admin list is still one journalled admin read per page, and nothing the viewer cannot read is drawn or counted. The server answers `GET /web?view=memories` and its admin and `display=atlas` forms with a redirect to the new paths; one memory opened by its id stays the server's view. Creating a workarea runs from the Workareas view through `POST /v2/workareas`, which now replays a recorded creation under the same `Idempotency-Key`; an old form that posts it to the server runs nothing. Fields join the API for the list: `include_text` on the `with_own` listing, `author_key_id` and `scan_finding` on each served memory, and `held_by`, `promoted_at`, valid time and `scan_finding` on the admin read's items, whose page now holds up to 200. Caddy, both compose routers and the chart's `web.ingressPaths` route the six new paths; upgrading a deployment means adding them to the proxy ([Run the web console](operations/web-console.md)).
