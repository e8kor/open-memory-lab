Fixed three ways content the scan should hold reached other agents ([ADR-0065](adr/ADR-0065-the-scan-is-a-versioned-compiled-in-rule-set-that-vetoes-leaked-keys-and-holds-what-a-reviewer-should-judge.md) d1, d5, d13, d14, d15, shaped by ADR-0074 d28; [ADR-0030](adr/ADR-0030-an-in-progress-workarea-serves-unreviewed-memories-inside-it-and-nothing-leaves-until-a-person-commits-it.md) d3). The rule set is now `oml-scan/1.1`. Every rule also reads the normalised text, with Unicode's default-ignorable characters removed and NFKC applied, so a zero-width character or fullwidth forms no longer hide an injection phrase. Tag characters pass only as one of the three RGI subdivision flags, read whole. Each version records the rule set it was scanned under, `scanned_under` (migration 0038, which reads existing rows as `oml-scan/1`), and inside an in-progress workarea another author's held version is served only when the current rule set scanned it and found nothing, in recall, listing, reads by id and claim edges, on both stores. `oml admin rescan --record-held` (`POST /v2/admin/rescan`) records each held version's findings under the current rule set, journalled as `scan.findings_recorded`. After upgrading, run `oml admin rescan --record-held`: until it runs, sibling agents in an in-progress workarea do not see held versions written before the upgrade.
