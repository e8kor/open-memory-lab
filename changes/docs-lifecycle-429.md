**The lifecycle review's answers are recorded as proposed amendments.** The operator answered the four open questions of the lifecycle review on 2026-11-18, and each answer is recorded, proposed, in the records that cite it (#429). The place carries the rules: an open workspace is development, a `protected` or `frozen` workspace is production for every reader, a published release is production wherever its workspace sits, and a key's binding only chooses which version it reads ([ADR-0001](adr/ADR-0001-the-constitution.md) d5; [ADR-0085](adr/ADR-0085-a-workspace-publishes-immutable-releases-that-one-person-cuts-and-another-ratifies-and-each-key-binds-to-the-tip-the-latest-release-or-a-pinned-one.md) D1). A `latest` key on a workspace with no published release is refused in a `protected` or `frozen` workspace, under the proposed code `release.none_published`, and reads the promoted tip, marked on every hit, in an open one (ADR-0085 D2). A release candidate is named by an id and its label is bound at publish, so a refused candidate never uses up a label; the label promises the manifest, and the served set is the manifest minus drops plus marked overlays (ADR-0085 D3). An import may land held in any open or protected workspace, never a frozen one (`import.target_frozen`), and in a protected or released workspace each imported version needs a person's verdict from someone other than the importer (`review.person_required`, `imported_needs_person`) ([ADR-0084](adr/ADR-0084-a-workspace-moves-between-servers-as-a-signed-bundle-that-lands-held-or-in-progress-and-is-reviewed-again-unless-its-source-server-is-pinned.md) D4; the import's mode exception in [ADR-0030](adr/ADR-0030-an-in-progress-workspace-serves-unreviewed-memories-inside-it-and-nothing-leaves-until-a-person-commits-it.md) d1 superseded). For the operator's batch: an admin fix is confirmed by another person wherever the fixed version is served to production, a cut refuses a member whose only verdict is `same_user` ([ADR-0089](adr/ADR-0089-an-admin-fixes-a-production-workspace-at-once-by-a-marked-break-glass-act-that-a-person-confirms-or-reverts-afterwards.md) d8), To do gains an "approved, not in a release" row, and the workspace page shows Drafts · Candidate · Published under Development / Staging / Production ([ADR-0083](adr/ADR-0083-the-memories-page-is-one-cockpit-with-approved-to-review-and-submitted-views-and-held-rows-never-appear-as-approved.md) d11). Nothing here is built; the release work builds it, and v0.8.2's in-progress-only import stands until then.
