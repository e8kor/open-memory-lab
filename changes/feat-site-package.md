The landing site is a deployable of its own ([ADR-0069](adr/ADR-0069-oml-s-design-system-is-the-source-of-truth-for-every-surface.md); [ADR-0070](adr/ADR-0070-the-web-console-is-a-client-of-the-public-http-api-in-a-crate-that-cannot-reach-the-application-core.md)). Its sources moved from `deploy/landing/` to `site/`, where `site/build.py` assembles the pages into `site/dist/` from `site/src/`, the design system's outputs in `site/design/` and the workspace version; `scripts/gen_design_tokens.py` now writes those outputs instead of the pages, which are byte-for-byte unchanged. Each release ships the pages as `oml-site-<version>.tar.gz`, summed in `SHA256SUMS` and signed with the other archives, and CI fails a pull request whose `site/dist/` differs from what its sources build. The documentation site now builds into `_site/` (`site_dir` in `mkdocs.yml`). `site/README.md` holds the Caddy example, which routes `/web` to `oml-web` once it runs as its own process.
