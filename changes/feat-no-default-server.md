- **No release names a server** ([ADR-0076](adr/ADR-0076-releases-ship-no-default-server-and-setup-asks-for-the-server-or-reads-it-from-the-key-or-the-environment.md)). The CLI, the Claude Code plugin, its hooks, the agent kit and the web pages no longer default to the maintainer's server. The plugin's `url` option is required again, with no default. `oml setup claude-code` takes the URL beside the key. Without one it asks for the server on a terminal. Off a terminal it refuses as `setup.no_server` before anything is sent, and it never pairs a key file with `OML_URL`. A hook with the plugin's key and no `url` prints `no_server` and loads nothing. `oml doctor` names `no_server`, `plugin_no_server` and `server_origin`. The web pages show the server's own address beside a new key, or say it is not configured. The agent kit's Cursor and Gemini CLI files read `OML_URL`. Its Codex CLI, VS Code and Claude Desktop files carry `https://oml-server.invalid/mcp`, which never resolves. `GET /v2/whoami` gains `shared`, `true` when the operator sets the new `server.shared` or opens sign-up. `oml sync` asks consent of a shared server and records it per server origin. A server whose whoami does not say is not asked about, and a recorded `oml.allowPublicServer=true` no longer counts. **Upgrading:** set the plugin's `url` once with `oml setup claude-code --url <server> --key-file <file>`. A script that ran setup with a key alone passes `--url`. A hosted server that is not open for sign-up sets `server.shared = true` in the deploy that upgrades it. The Python and TypeScript SDKs are regenerated for `Whoami.shared`.
