**Own listings filter by kind and state lists, and `mine` lists a person's own rows** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d8 item 3, [ADR-0083](adr/ADR-0083-the-memories-page-is-one-cockpit-with-approved-to-review-and-submitted-views-and-held-rows-never-appear-as-approved.md) d3, d14; #409). `GET /v1/memories` with `with_own`, `author` or the new `mine=true` takes `kind` as a comma list of kinds, `guardrail` among them, where a `kind` beside `with_own` used to be refused, and `state` as a comma list of `held`, `promoted`, `superseded`, `rejected`, `demoted` and `withdrawn`. `mine=true` lists the caller's own key set with no scoped part under one cursor: every key of the person for a person's session key, the key alone for any other key; `author` narrows it to one own key. `promoted_since=<instant>` keeps only the promoted rows approved at or after the instant and leaves every other state whole. A malformed value is `request.validation` naming its field. The plain scoped listing is unchanged: one `state`, one `kind`.

**The workspace read counts approved claims by kind** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d8 item 7, d10; #409). `GET /v2/workspaces/{workspace}` serves `approved_by_kind`, an object keyed by kind that names only the kinds with at least one approved claim on that workspace alone, not its subtree. **Preview answers what a write would do without writing it** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d5, d8 item 1, d10; #409). `POST /v1/memories/preview` takes the body of `POST /v1/memories`, or of a supersession with `replaces` naming the version replaced, and runs every check capture runs through the same pipeline, stopping before anything is journalled, held or metered; no `Idempotency-Key` is read, so nothing is recorded or replayed. It answers `would_capture`, the scan's `findings`, `needs_person`, `body_bytes` and `budget_tokens`, and for a skill its prompt name `offered_as` and the same-named skills it shadows or is shadowed by along its chain, for a guardrail its rule in canonical `oml-gr/1` form and `set_after`, the set size an agent at its workspace loads once it is approved, against the cap of 12. A refusal of authority (no or a bad key, the request rate, the verb ceiling, any `access.*` refusal, an unreadable target) is the HTTP error submit or supersede answers; every other refusal capture would make answers `200` with `would_capture: false` and `refusal` in the error object's shape. The Rust SDK gains `preview`, and `oml doctor` warns when the server does not serve the route ("this server predates the builder").
