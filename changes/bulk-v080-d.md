**Readings for the builder, the cockpit and To do (2026-11-18).** [ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d10 and [ADR-0083](adr/ADR-0083-the-memories-page-is-one-cockpit-with-approved-to-review-and-submitted-views-and-held-rows-never-appear-as-approved.md) d14 record six readings for the operator's batch: preview answers an authority refusal as an HTTP error and a capture-time refusal inside its `200` body; a person's session reviewer key starts a held claim where it holds reviewer and reader; `approved_by_kind` names only non-zero kinds and the Memories count sums the kinds the cockpit lists; any key may send `mine=true` and gets its own set; the To do counts serve only the groups that are built; and To do's Next reads the oldest held row itself.

**Own listings filter by kind and state lists, and `mine` lists a person's own rows** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d8 item 3, [ADR-0083](adr/ADR-0083-the-memories-page-is-one-cockpit-with-approved-to-review-and-submitted-views-and-held-rows-never-appear-as-approved.md) d3, d14; #409). `GET /v1/memories` with `with_own`, `author` or the new `mine=true` takes `kind` as a comma list of kinds, `guardrail` among them, where a `kind` beside `with_own` used to be refused, and `state` as a comma list of `held`, `promoted`, `superseded`, `rejected`, `demoted` and `withdrawn`. `mine=true` lists the caller's own key set with no scoped part under one cursor: every key of the person for a person's session key, the key alone for any other key; `author` narrows it to one own key. `promoted_since=<instant>` keeps only the promoted rows approved at or after the instant and leaves every other state whole. A malformed value is `request.validation` naming its field. The plain scoped listing is unchanged: one `state`, one `kind`.

**A person's web key revises what their agents wrote** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d2, d8 item 2; #409). `POST /v1/memories/{artifact_id}/supersede` from a person's session web key now admits a target any key of the same person wrote, read the one way `same_user` reads it, where a writer used to supersede only its own key's rows. The successor is held and reviewed by another key as before. Another author's row is still `access.author_only`, and an agent's key still supersedes only its own rows.

**A person's reviewer key starts a held claim** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d2, d8 item 5, d10; #409). `POST /v1/memories` from a person's session key whose role is reviewer, `<user>-review`, writes a new claim where that key holds reviewer and reader, a shared workspace included. The version is held and readable by its author alone, its lineage excludes the key from judging it, and outside the person's root no key of the same person counts a verdict on it (`review.author_in_lineage` with `details.reason: same_person`). Every other reviewer key, a tenant reviewer included, is still `access.verb_ceiling`, and agent keys gain nothing.

**The workspace read counts approved claims by kind** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d8 item 7, d10; #409). `GET /v2/workspaces/{workspace}` serves `approved_by_kind`, an object keyed by kind that names only the kinds with at least one approved claim on that workspace alone, not its subtree. A claim counts once when its tip is promoted and is not a retirement, so a replaced version or a held successor adds nothing and a retired claim counts nothing. The Rust SDK's `WorkspaceView` reads it, `None` from an older server, and its `MemoryQuery` sends `mine`, a kind list and `promoted_since`.

**Preview answers what a write would do without writing it** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d5, d8 item 1, d10; #409). `POST /v1/memories/preview` takes the body of `POST /v1/memories`, or of a supersession with `replaces` naming the version replaced, and runs every check capture runs through the same pipeline, stopping before anything is journalled, held or metered; no `Idempotency-Key` is read, so nothing is recorded or replayed. It answers `would_capture`, the scan's `findings`, `needs_person`, `body_bytes` and `budget_tokens`, and for a skill its prompt name `offered_as` and the same-named skills it shadows or is shadowed by along its chain, for a guardrail its rule in canonical `oml-gr/1` form and `set_after`, the set size an agent at its workspace loads once it is approved, against the cap of 12. A refusal of authority (no or a bad key, the request rate, the verb ceiling, any `access.*` refusal, an unreadable target) is the HTTP error submit or supersede answers; every other refusal capture would make answers `200` with `would_capture: false` and `refusal` in the error object's shape. A document's passages are not served yet; they come with documents (#475). The Rust SDK gains `preview`, and `oml doctor` warns when the server does not serve the route ("this server predates the builder").

**A person's reviewer key lists `remember` where it may start a claim** ([ADR-0082](adr/ADR-0082-a-person-builds-and-edits-a-workspaces-skills-guardrails-and-documents-in-the-console-each-edit-a-held-version-under-the-persons-own-keys.md) d11; #409). `my_effective_verbs` on `GET /v2/workspaces/{workspace}` lists `remember` for a person's session reviewer key where it holds reviewer and reader, so the verbs it lists are the verbs it may use; a tenant reviewer key lists none and its submit stays `access.verb_ceiling`. A skill's preview names no same-named skill the key cannot read.
