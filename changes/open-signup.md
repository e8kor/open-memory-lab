- **Open sign-up: anyone signs in with Google or GitHub and gets a private root under quotas** ([ADR-0068](adr/ADR-0068-anyone-signs-in-and-gets-a-private-root-under-quotas-when-the-operator-opens-sign-up.md), proposed). With `signup.mode = open`, which is off by default, a provider-verified email that no entry holds reaches a terms page. Accepting it creates the entry under a drawn user in the `signup.tenant`, journalled as `web.signed_up` with the terms version, and issues the person's root, `<user>-web` and `<user>-review`. The person then lands on `/web/start`, which has three steps: choose a client, get the credential (a connect code for claude.ai, a key and the plugin commands for Claude Code, a URL and key for other tools), and wait for the first connection and first memory, which a five-second status poll shows. A second person cannot read, count or recall the first person's memories over HTTP, MCP or the pages. The person's agents' writes are approved by their reviewer key, and each promotion is marked `same_user`. The sign-up tenant's people are held to quotas: 1,000 memories, 5 keys, 5 connections and 120 requests a minute per key. Past one they get `limit.quota` or `limit.rate` with `Retry-After`, counted on `oml_quota_refused_total`, and an admin raises a person's limit on `/web/admin/users` (`web.quota_set`). A person exports everything as JSON and asks for deletion (`web.deletion_requested`). The admin closes a request by disabling the person (`web.user_disabled`, a cut-off of each agent key, then `web.deletion_closed`), and the memories stay until erasure. Sign-ups are limited per client address. `GET /v2/web/users` and `oml doctor` name people near a quota, pending deletions and a missing trusted proxy. Migration 0037 adds the rows.
