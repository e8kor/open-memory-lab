**The PostgreSQL schema has its page (#439).** `docs/data/postgres-schema.md`, which the migrations' table and column comments name as the schema's owning page, now exists under Reference. `scripts/gen_postgres_schema.py` writes it from the catalog after every file under `migrations/` has run on a throwaway database: each table's purpose from its `COMMENT`, its columns with types, nullability and defaults, its checks and keys, its row-level security and policies, the privileges of the owner, serving and lake writer roles, and its partitions. The docs workflow's `PostgreSQL schema page matches the migrations` job runs it with `--check` against `pgvector/pgvector:pg17`, so a migration that changes the schema fails CI until the page is regenerated. The storage architecture page links to it.
