What it costs

Open Memory Lab gives every tool the same approved memory. The cost is review time: a new memory reaches the team only after a person or a reviewer agent has looked at it. A person can approve or reject a listed batch in one act, on the admin Review page or with oml review list, and each memory still gets its own signed verdict.

Reuse it in production

Your apps' retrieval can recall the same approved memories through the HTTP API or the Python and TypeScript clients, filtered by workarea, kind and repository. Each hit carries its version, author, source anchor and the words it matched.

{{GLYPH:blocked}}

Checks before anything is shared

A rule-based scan, oml-scan/1.1, refuses private keys, known providers' API tokens, user:password pairs in a URL or after curl -u, passwords set in config (DB_PASSWORD=…) and any field over 1 MiB, before anyone reads them. Prompt-injection phrases, hidden Unicode and long base64 blobs are recorded as findings on the held memory and shown on its review card; the memory still waits for review like every other. oml admin rescan reports matches already stored.

{{GLYPH:held}}

Review by someone else

Each memory waits for a person or reviewer agent who didn't write it; the key that wrote it never approves it. A person can approve a listed batch in one act.

{{GLYPH:gate}}

Team rules, checked

Approved rules such as "never push to the release branch" load at the start of every Claude Code session with the plugin. A rule with a check refuses or asks before a matching tool call.

{{GLYPH:superseded}}

Lineage on every memory

A correction is a new version that supersedes the old, and every version stays fetchable. A read can ask for memory as it was at a past instant, under today's access. Each names its author and, where given, the repository, commit and file it came from; once oml sync finds that file changed, recall marks it stale.

{{GLYPH:superseded}}

A signed record of every change

Every write, approval and rejection is signed and chained in an append-only history, so an edit by anyone without the signing key shows.

{{GLYPH:can}}

Control over who reads what

Memory is split into workareas, such as one per team or project. A key reads only where it is granted, and a denial always wins. Recall across several of the workareas a key reads is off until a tenant admin turns it on, and never reaches one it cannot read. Admins issue keys and grants; their verdicts on content are refused.

{{GLYPH:promoted}}

Repeatable answers

The default search is BM25 with no model: the same query over the same approved memories returns the same hits in the same order. Where the server loads its 268 MB model, bm25-sparse finds more: 0.983 success@5 on the recall eval against 0.934 for the default (how it was measured).

{{GLYPH:shared}}

Yours to run

Self-host on your own PostgreSQL 17 or later, and every memory, key and log stays in your infrastructure. The server and its web console run as two processes; Docker Compose, oml quickstart and the Helm chart start both. On the hosted server, each organization's data is isolated by PostgreSQL row-level security.
