# Open Memory Lab agent kit @VERSION@

This kit connects coding agents other than Claude Code to an Open Memory Lab server's MCP
endpoint, `/mcp`. It holds one configuration per tool, an `AGENTS.md` block that tells the agent
how to recall and remember, and, for Gemini CLI, the session-start hook the Claude Code plugin
runs. Every write the agent makes is held until a different identity approves it, so a fact it
stores is not shared the moment it stores it.

Every file in the kit is generated by `scripts/package_agent_artifacts.py` in the
[repository](https://github.com/e8kor/open-memory-lab), and `scripts/check_agent_kit.py` checks
it on every pull request. For Claude Code, install the `oml` plugin instead: see the plugin's
README in the repository, `plugins/oml/README.md`.

## Verify, then install

Every release signs this archive keyless with cosign, under the release workflow's identity, and
lists it in `SHA256SUMS`. Verify it before you extract it:

```sh
v=@VERSION@
base=https://github.com/e8kor/open-memory-lab/releases/download/v$v
curl -fsSLO "$base/oml-agent-kit-$v.tar.gz" -O "$base/oml-agent-kit-$v.tar.gz.sigstore.json"
cosign verify-blob \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github.com/e8kor/open-memory-lab/\.github/workflows/release\.yml@refs/tags/.*$' \
  --bundle "oml-agent-kit-$v.tar.gz.sigstore.json" "oml-agent-kit-$v.tar.gz" \
  && tar -xzf "oml-agent-kit-$v.tar.gz"
```

On Windows, download `oml-agent-kit-$v.zip` and its `.zip.sigstore.json` bundle, run the same
`cosign verify-blob` on them, and extract the zip only after it exits 0. An archive that does not
verify is not a release.

## Before you start

Every configuration reads the agent's key from the environment variable `OML_API_KEY`; none
holds a key. Issue the key with `oml keys issue-agent`, which gives it a writer grant and a
reader grant on the agent's workarea, and export it in the shell that starts the tool:

```sh
export OML_API_KEY=oml_...                  # this agent's one key
```

Give each agent its own key. Attribution, and the rule that a reviewer never reviews their own
work, both depend on it.

Every configuration names `http://127.0.0.1:8080/mcp`. Replace `http://127.0.0.1:8080` with your
server's address, keeping `/mcp`.

## The tools

Each entry names the file to copy, where it goes, and the page that documents that format, with
the date it was read. Where a tool's page does not settle a detail, the entry says so.

### OpenAI Codex CLI

`codex/config.toml` holds one `[mcp_servers.oml]` table. Add it to `~/.codex/config.toml`, or to
`.codex/config.toml` in a project Codex trusts. Codex sends the value of the variable that
`bearer_token_env_var` names as the bearer token
([Codex MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli), fetched
2026-11-03; `developers.openai.com/codex/mcp` redirects there).

### Cursor

Copy `cursor/.cursor/mcp.json` to `.cursor/mcp.json` in your project, or merge its `oml` entry
into `~/.cursor/mcp.json` for every project. Cursor resolves `${env:NAME}` in `url` and `headers`
([Cursor MCP documentation](https://cursor.com/docs/context/mcp), fetched 2026-11-03).

Cursor documents a `sessionStart` hook, but its output field is `additional_context` and its input
carries `workspace_roots` rather than `cwd`
([Cursor hooks](https://cursor.com/docs/agent/hooks), fetched 2026-11-03), while
`oml hook session-start` writes Claude Code's `hookSpecificOutput.additionalContext` and reads
`cwd`. The kit wires no Cursor hook.

### Gemini CLI

Merge `gemini/.gemini/settings.json` into `~/.gemini/settings.json`, or into
`.gemini/settings.json` in your project. Gemini CLI reads a streamable HTTP server from
`httpUrl` with `headers`
([MCP servers with Gemini CLI](https://github.com/google-gemini/gemini-cli/blob/main/docs/tools/mcp-server.md),
fetched 2026-11-03), and resolves `$VAR` or `${VAR}` in every string value of `settings.json`
when it loads the file
([configuration reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md),
fetched 2026-11-03), so `Bearer ${OML_API_KEY}` becomes the key.

The same file wires a `SessionStart` hook to the command the Claude Code plugin runs:
`oml hook session-start`, guarded so that without `oml` on `PATH` it exits 0 in silence and a
failing `oml` still exits 0. Gemini CLI fires `SessionStart` on startup, resume and clear, passes
`cwd` on stdin as JSON, and adds `hookSpecificOutput.additionalContext` to the session; its
`timeout` is in milliseconds, here 10000
([hooks](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/index.md) and
[hooks reference](https://github.com/google-gemini/gemini-cli/blob/main/docs/hooks/reference.md),
fetched 2026-11-03). The hook needs the `oml` CLI on `PATH` and reads `OML_URL` and
`OML_API_KEY`; set `OML_URL` to the server's address without `/mcp`. Gemini CLI warns before it
runs a project hook it has not seen. Unverified: which shell Gemini CLI runs the command in, so
whether the POSIX guard works on Windows; the pages do not say.

### VS Code and GitHub Copilot

Copy `vscode/.vscode/mcp.json` to `.vscode/mcp.json` in your workspace. The VS Code format keeps
servers under a top-level `servers` object, and an HTTP server takes `type: "http"`, `url` and
`headers`
([MCP configuration reference](https://code.visualstudio.com/docs/agents/reference/mcp-configuration),
fetched 2026-11-03). Unverified: that page lists `${env:NAME}` as the VS Code format's variable
for the environment, but its own `headers` example uses `${input:...}`, so that `${env:OML_API_KEY}`
resolves inside a header has not been run. If it does not, replace it with an input variable,
which VS Code prompts for and stores.

### Claude Desktop

`claude-desktop/claude_desktop_config.json` goes in `~/Library/Application Support/Claude/` on
macOS, `%APPDATA%\Claude\` on Windows or `~/.config/Claude/` on Linux
([Connect to local MCP servers](https://modelcontextprotocol.io/docs/develop/connect-local-servers),
fetched 2026-11-03). That file starts local servers from `command` and `args`; a remote server is
otherwise added under Connectors in the app
([custom connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp),
fetched 2026-11-03). The kit's entry runs the stdio bridge `mcp-remote` with `npx`, which forwards
to `/mcp` and expands `${OML_API_KEY}` in its `--header` argument from its own environment
([mcp-remote README](https://github.com/geelen/mcp-remote), fetched 2026-11-03).

Unverified, all three: that Claude Desktop passes an `OML_API_KEY` from your login environment to
the bridge, which depends on how the app was started; the bridge itself, which is not an
Anthropic or Open Memory Lab component; and Windows, where the bridge's README reports that
spaces inside `args` are mangled. Adding the server under Connectors with an `Authorization`
request header is the route the app documents.

## AGENTS.md

`AGENTS.md` holds the recall and remember guidance of the Claude Code plugin's skill, between
`<!-- oml:begin ... -->` and `<!-- oml:end -->`. Paste the block into the `AGENTS.md` (or the
tool's own instructions file) of the project the agent works in. The block is copied section by
section from `plugins/oml/skills/oml-memory/SKILL.md`, so the two say the same thing; the skill's
section on the plugin's connection is left out.
