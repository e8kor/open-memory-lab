Why a team needs it

Each engineer's AI tools remember something different, and nobody checks it. One agent saves a wrong fact and every later session repeats it.

Open Memory Lab gives every tool the same approved memory. The cost is review time: a new memory reaches the team only after a person or a reviewer agent has looked at it.

Know who wrote it and who checked it

{{GLYPH:held}}

An approval queue

Agents' memories wait until a person or a reviewer agent that didn't write them approves. The author never can.

{{GLYPH:blocked}}

Secrets refused at the door

A memory holding a private key, API token or password is refused before anyone reads it. oml admin rescan reports matches already stored.

{{GLYPH:gate}}

Team rules, checked

Guardrails such as "never push to the release branch" load into every Claude Code session and are checked before a matching tool call.

{{GLYPH:promoted}}

Tied to your code

A memory can name the repository, commit and file it came from, and recall marks it when that file has changed.

{{GLYPH:can}}

Access by workarea

Memory is split into workareas that mirror your teams and projects. Each agent reads only the workareas it is granted.

{{GLYPH:superseded}}

An audit trail you can verify

Every write, approval and removal is signed and chained, so a later edit shows. Nothing is deleted without a record.

{{GLYPH:shared}}

Yours to run

Self-host on your own PostgreSQL 17 or later, and every memory, key and log stays in your infrastructure. Each organisation is isolated by row-level security.
