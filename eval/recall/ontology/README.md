# Recall eval, ontology arms: what a small reviewed vocabulary buys

**Run:** 2026-11-04, branch `feat/ontology-metadata`, offline, over the recall eval's data
version 1 (200 memories of one fictional invoicing crew, 121 queries in 11 categories of 11),
as `feat/recall-eval` held it. `eval/recall/` on main is now data version 2 (143 queries, adding
22 unanswerable ones); these arms read `../corpus.json` and `../queries.json` and have not been re-run
on version 2. Every number below is in
[results/tables.md](results/tables.md), regenerated by `tables.py` from `results/*.json`.
[ADR-0051](../../../docs/adr/ADR-0051-a-memory-says-what-it-is-about-in-reviewed-terms-and-recall-finds-it-by-them.md)
takes its decisions from this run.

**Headline.** A curated vocabulary of 80 terms, with 0 to 3 terms on each memory, used to find
memories by the terms a query names, raises BM25's nDCG@10 from 0.84 to 0.88 (paired 95%
interval +0.003 to +0.061) and its paraphrase success@5 from 0.64 to 0.82, level with the
committed dense and hybrid runs on nDCG@10 (0.85, 0.88) and on paraphrase (0.82), with no
embedding stored. Using the same labels to add synonyms to the query text does not help BM25:
success@1 falls from 0.79 to 0.72. Over today's any-word index the term list adds more
(success@5 0.73 to 0.85, nDCG@10 0.59 to 0.74). With a third of the tags dropped and a fifth
replaced at random, the same term list costs BM25 0.11 nDCG@10: the terms help only while they
are right.

## How it was built

[DISCIPLINE.md](DISCIPLINE.md) records the order: the vocabulary and the tags were committed
(`1d33df0`) before `run.py` existed and before `queries.json` was opened in this lane.

- **Vocabulary** ([vocabulary.json](vocabulary.json)): 80 terms in four facets, component 11,
  technology 26, topic 36 and process 7. Each term has a preferred label and alternative labels
  (abbreviations, product names, plural and colloquial forms): 541 labels, 6.8 a term.
- **Tags** ([tags.txt](tags.txt)): 0 to 3 terms on each memory, for what the memory is about,
  the choice a writing agent makes from candidate terms. 200 memories, 373 tags, every term used.
- **Label matching** (`LabelMatcher` in `run.py`): a term matches a text when one of its labels
  occurs in it as a contiguous run of Snowball-stemmed words. No model; a scan of 541 labels.

## Arms

All arms return at most `k = 10`. The base methods are the committed ones:

| arm | what it is |
|---|---|
| `any` | `../baselines.py`'s `pg_simple_or` on a throwaway PostgreSQL 18.6: the served `simple` index, words joined by OR, `ts_rank_cd`. It reproduces the committed `pg_simple_or` ranking on all 121 queries |
| `bm25` | `../baselines.py`'s `bm25`, unchanged (BM25Okapi, Snowball stems, stop words dropped) |
| `+syn` | the query's words plus every label of every term a query label matched, the added words at half weight (expansion of the text) |
| `+term` | the base list fused by reciprocal rank (k = 60) with a **term list**: the memories tagged with a term the query matched, more matched terms first, then base order |
| `+syn+term` | both |
| `+syn+boost` | `+syn`'s scores over the top score, plus 0.15 for each matched term the memory carries |
| `+rareterm` | `+term`, counting only terms that tag at most 10 memories |
| `dense`, `hybrid_rrf` | the committed `../results/` runs (bge-small-en-v1.5; BM25 and dense fused) |

Three tag sets: **curated** (`tags.txt`), **lexical** (the three terms whose labels occur most
in the memory's own text: what a server-side label matcher would attach with no judgement), and
**noisy** (curated, each tag dropped with p = 0.3 and replaced by a random term with p = 0.2,
seed 7: a stand-in for careless automatic tagging).

## What the numbers say

1. **Find by term, do not rewrite the text.** Adding every label of a matched term to a BM25
   query makes 44 queries worse and 26 better: a term's labels are many and some are common
   words (`topic:authentication` has 16), and BM25 ranks them as evidence. Fusing a separate
   list of the memories *tagged* with the term keeps the base order for the words the query
   holds and adds the memories the words missed: 30 better, 11 worse. Over today's any-word
   index, which has no rarity weights, both help, and the term list helps most.
2. **The paraphrase gain is the term list's.** `q013` ("where do pods get their credentials
   from") reaches the secrets memories through `topic:secrets`'s label `credentials` (nDCG@10
   0.12 → 0.80); `q017` ("warehouse query cost too high") through `cmp:analytics`'s label
   `warehouse` and `topic:cost` (0.32 → 1.00); `q018` ("gitops … tool") through `tech:argo-cd`'s
   label `gitops` (0.00 → 0.47). `q019` ("who gets woken up at night …") matches no label and
   gains nothing: a vocabulary helps only where a curator wrote the word.
3. **The false matches are broad terms on common words.** The queries `bm25+term` made worse by
   more than 0.05 matched a term through an ordinary word: "planned" → `proc:planning`,
   "committed" → `proc:git-workflow`, "invoices" → `topic:invoicing`, "api" → `cmp:api`. Dropping
   every term that tags more than 10 memories (`+rareterm`) did not help (nDCG@10 0.86 against
   0.88), because the broad terms carry true matches too. A label like "commit" is the
   curator's to fix; the per-query results show which ones.
4. **Tag quality decides the sign.** Curated tags +0.03 nDCG@10; tags a label matcher attaches
   with no judgement +0.01, not distinguishable from zero; noisy tags −0.11. The boost variant
   is robust to noise and gains nothing with good tags. So terms belong where a reviewer reads
   them, and the server offers candidates rather than attaching them.
5. **It does not beat hybrid.** `bm25+term` ties `hybrid_rrf` on nDCG@10 (difference −0.03 to
   +0.03) and trails it on success@5 by 0.025, inside the interval. It reaches dense's
   paraphrase number on this set without an embedding index; that is all this run can claim.

## Limits

- **One model wrote everything.** The corpus, the queries and their labels (`feat/recall-eval`)
  and the vocabulary and the tags here come from the same model family. A curator's synonyms and
  a query writer's paraphrases drawn from one model's lexicon overlap more than two people's
  would, so the paraphrase gain is an upper bound. Five query fragments were known before the
  vocabulary was written (DISCIPLINE.md).
- **11 queries a category.** One query moves a category by 0.09; the overall intervals are the
  evidence, the per-category cells are not.
- **One workarea, one kind, no held rows, no unanswerable queries.** False positives on queries
  OML cannot answer are unmeasured (FR-83); a term list returns tagged memories whenever a label
  matches, so they are likely to rise.
- **Offline.** Latency is not measured.
- **Curation cost is unmeasured.** Writing 80 terms and 373 tags took one pass of the eval's
  author; what curation and review cost a real crew is ADR-0051's FR rows to measure.
